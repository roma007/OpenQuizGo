## 1. 结论

**通过。** 家长端可创建 6 位房间码；孩子设备加入后先答；家长设备轮询进入答题；双方提交后生成比分与逐题结果；同设备模式保持可用。

## 2. 交付

- 迁移 `00017_battle_room.sql` + `00018_battle_waiting_status.sql`：`mode`、`join_code`、`waiting` 状态；
- 服务端 `Create` 支持 `mode=room`，`Join` 按房间码幂等加入，未加入提交 409；
- 房间码 6 位、去掉易混淆字符，仅家庭内孩子可用；
- 家长端对战入口：`开始对战`（同设备）、`双设备房间`、`输入房间码加入`；
- 创建方显示房间码并 2 秒轮询；加入方孩子答题后等待家长；结果页共用；
- 离开页面/进入结果停止轮询。

## 3. 验证


服务端房间用例覆盖：创建 waiting + 6 位码、错误码 404、加入→child_turn、重复加入幂等、孩子提交→parent_turn、家长提交→finished、结束后不返回房间码。

模拟器实测（家长设备）：

| 步骤 | 结果 |
| --- | --- |
| 孩子卡片 → 亲子对战 → 双设备房间 | 显示房间码 `MEJ79P` 与等待提示 |
| 另一设备（API 模拟）加入并提交孩子答案 | 家长端 2 秒内切换为「家长答题」 |
| 家长答完 5 题 | 结果页「平局 5:5」，逐题显示双方对错 |
| 数据库 | `mode=room, status=finished, child_score=5, parent_score=5` |

截图：`docs/acceptance/phase21/01-room-code.png`、`02-parent-turn.png`、`03-room-result.png`。

## 4. 限制

- 第二个物理设备不可用，孩子端界面由 Widget 测试覆盖，实际加入由 API 模拟；
- 轮询间隔 2 秒，非 WebSocket 实时；
- 房间码无过期时间，结束后仍保留在数据库但接口不再返回；
- 同一家庭账号可操作双方，未区分设备身份。

## 5. 后续

- 断线重连与对局恢复提示。
