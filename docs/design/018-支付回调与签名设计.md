## 1. 目标

为真实支付渠道预留标准回调入口：

- 渠道服务端通过 HMAC-SHA256 签名回调，无需家长令牌；
- 回调按 `order_no` 幂等更新订单与会员；
- 订单记录支付渠道与外部交易号；
- 本地可用 curl/脚本模拟渠道回调，无需真实商户号。

## 2. 回调协议

`POST /v1/payments/callback`

请求头：`X-Payment-Signature: <hex hmac-sha256>`

请求体（原始字节参与签名）：

```json
{"order_no":"M2026...","trade_no":"WX123456","status":"paid"}
```

签名算法：

```text
signature = hex(hmac_sha256(PAYMENT_CALLBACK_SECRET, raw_body))
```

## 3. 配置

| 环境变量 | 说明 |
| --- | --- |
| `PAYMENT_CALLBACK_SECRET` | 回调签名密钥；dev 默认 `dev-payment-callback-secret`，生产必须显式配置 |

密钥为空时回调返回 503 `PAYMENT_DISABLED`。

## 4. 处理规则

1. 校验签名（常量时间比较），失败 401 `SIGNATURE_INVALID`；
2. 解析 `order_no` / `trade_no` / `status`，仅支持 `paid`；
3. 按 `order_no` 锁定订单：
   - 不存在 → 404；
   - 已退款 → 409 `ORDER_ALREADY_REFUNDED`；
   - 已支付 → 幂等返回，不重复延长；
   - 待支付 → 标记 paid，`channel=callback`，记录 `external_trade_no`，延长会员；
4. 响应 `{"status":"ok","order_no":"...","paid":true}`。

## 5. 数据模型

```sql
alter table membership_order add column external_trade_no text not null default '';
```

`channel` 现有字段区分 `mock` / `callback`。

## 6. 前端

- 管理端订单表增加「渠道」列（模拟支付/渠道回调）；
- 家长端无变化，订单仍显示套餐与状态。

## 7. 风险

| 风险 | 对策 |
| --- | --- |
| 伪造回调 | HMAC 密钥 + 常量时间比较 |
| 重复回调重复加时长 | 订单行锁 + 已支付幂等 |
| 回调重放 | 订单已支付返回成功但不重复处理；外部交易号留存便于对账 |
| 生产误用 dev 密钥 | 生产环境必须显式配置，否则回调禁用 |
| 回调延迟/乱序 | 只处理 pending→paid；退款后回调拒绝 |
