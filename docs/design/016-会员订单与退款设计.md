## 1. 目标

补齐会员订单生命周期：管理端可查看全部订单并执行模拟退款；退款后自动回退会员到期时间，权益随到期状态立即失效。

不接入真实支付渠道；退款为本地模拟操作，用于验证业务闭环。

## 2. 规则

- 只有 `paid` 订单可退款；`pending` / `cancelled` 拒绝；
- 退款幂等：`refunded` 订单再次退款直接返回当前状态，不重复扣减；
- 退款时从当前会员到期时间减去该订单的 `duration_days`：
  - 结果晚于当前时间 → 仍为 active；
  - 结果早于当前时间 → 置为 expired，权益立即失效；
- 退款不删除订单，保留快照与退款时间；
- 管理端订单列表分页，可按状态筛选。

## 3. 数据模型

```sql
alter table membership_order
  drop constraint membership_order_status_check,
  add constraint membership_order_status_check
    check (status in ('pending','paid','cancelled','refunded'));
alter table membership_order add column refunded_at timestamptz;
```

## 4. 接口（管理员 `membership.read/write`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/v1/admin/membership/orders?status=&limit=&offset=` | 订单分页 |
| POST | `/v1/admin/membership/orders/{id}/refund` | 模拟退款 |

响应订单增加 `refunded_at`。

## 5. 前端

- 管理端会员页改为两个 Tab：套餐 / 订单；
- 订单表显示订单号、套餐、金额、状态、创建/支付时间、退款按钮；
- 退款前二次确认，成功后刷新列表并提示；
- 家长端订单状态新增「已退款」。

## 6. 风险

| 风险 | 对策 |
| --- | --- |
| 重复退款导致重复扣减 | 事务锁 + `refunded` 幂等 |
| 退款导致到期时间为负 | 直接置 expired，不保留负数 |
| 多笔订单叠加后退款顺序 | 统一从当前到期时间扣减，结果符合业务预期 |
| 真实支付接入后语义变化 | 本期明确为模拟退款，后续按渠道回调调整 |
