## 1. 背景与目标

### 现状与问题

平板模拟器走查时确认，两端 Android 图标并不统一：

| 端 | 现状 | 问题 |
| --- | --- | --- |
| 孩子端（`tv/`，电视 + 平板） | manifest 没有 `android:icon`，`res/` 下没有任何图片资源 | 桌面显示 Android 默认机器人图标；Android TV 也没有 `android:banner` |
| 家长端 Android | `mipmap-*/ic_launcher.png` 仍是 Flutter 新建项目的默认蓝色 F | 与品牌不一致 |
| 家长端 iOS | `AppIcon.appiconset` 已使用官方亲子 logo | 无需改动 |
| 官方品牌资源 | `docs/brand/logo-*.png`、`logo.svg` | 尚未落到 Android 两端 |

### 本次目标

- G1 孩子端在平板桌面显示官方 logo，电视桌面有对应 banner。
- G2 家长端 Android 显示官方 logo，包含自适应图标与圆形图标。
- G3 两端图标都从 `docs/brand/logo-1024.png` 生成，风格一致。
- G4 不改应用名、不改业务代码、不改 iOS 图标。

### 非目标

- 不做登录页/应用内 logo 改版。
- 不重新设计品牌标识，不修改 `docs/brand/` 母版。
- 不做 Android 13 主题图标（monochrome）与动态取色适配；后续需要再单独做。
- 不改应用名称（孩子端仍为「OpenQuizGo 守护端」，家长端仍为「电视时间管家」）。

## 2. 需求与验收标准

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| R1 | 孩子端平板图标 | 平板应用抽屉/桌面显示官方亲子 logo，而不是默认机器人 | P0 |
| R2 | 孩子端电视图标与 banner | Android TV Leanback 桌面显示 320×180 banner，应用图块不再空白/默认 | P0 |
| R3 | 家长端 Android 图标 | 各密度与自适应图标均显示官方 logo，圆形图标一致 | P0 |
| R4 | iOS 不回归 | 家长端 iOS 图标保持现有官方 logo | P1 |
| R5 | 构建通过 | `tv` 的 `assembleDebug` 与家长端 `flutter build apk --debug` 均成功 | P0 |
| R6 | 无行为变化 | 不改包名、版本号、接口、权限与页面逻辑 | P0 |

## 3. 方案对比与选型

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A 只放传统 PNG | 各密度只放 `ic_launcher.png` | 改动最小 | Android 8+ 会被套白底/圆框，观感差 | 不采用 |
| B 传统 PNG + 自适应图标 | 传统图标兜底，API 26+ 用 `mipmap-anydpi-v26` 自适应图标 | 各版本观感一致，符合 Android 规范 | 需要多生成一层背景图 | **采用** |
| C 引入图标生成库/依赖 | 在构建时动态生成 | 可复现 | 增加依赖与构建复杂度，收益低 | 不采用 |

选型理由：图标是静态资源，一次性从母版导出即可；采用 B 兼顾老版本与 Android 8+ 的遮罩效果。

## 4. 总体架构

### 4.1 资源来源与尺寸

统一从 `docs/brand/logo-1024.png` 生成，母版为深色满版方形。

| 用途 | 目录 | 尺寸 |
| --- | --- | --- |
| Android 传统图标 | `mipmap-mdpi/hdpi/xhdpi/xxhdpi/xxxhdpi` | 48 / 72 / 96 / 144 / 192 |
| 自适应背景层 | 同上（`ic_launcher_background.png`） | 108 / 162 / 216 / 324 / 432（108dp 画布） |
| 自适应前景层 | `drawable-nodpi/ic_launcher_foreground.png` | 透明 1×1（缩放后仍透明） |
| 圆形图标 | 与传统图标同尺寸 | 48 / 72 / 96 / 144 / 192 |
| TV banner | `drawable-xhdpi/tv_banner.png` | 320×180，不透明 |

自适应图标采用「整张 logo 作为背景层 + 透明前景层」：logo 四周本身有安全留白，按 96% 居中绘制，避免圆形遮罩切到外环。

### 4.2 两端改动

- 孩子端 `tv/app/src/main/AndroidManifest.xml`：
  - `<application>` 增加 `android:icon="@mipmap/ic_launcher"`、`android:roundIcon="@mipmap/ic_launcher_round"`、`android:banner="@drawable/tv_banner"`。
  - 新增 `mipmap-*`、`mipmap-anydpi-v26`、`drawable-nodpi`、`drawable-xhdpi` 资源。
- 家长端 `parent/android/app/src/main/AndroidManifest.xml`：
  - `<application>` 增加 `android:roundIcon="@mipmap/ic_launcher_round"`（`android:icon` 已存在）。
  - 替换 `mipmap-*/ic_launcher.png`，新增自适应图标与 `ic_launcher_round`。
- iOS：不动。

### 4.3 目录结构影响

```
tv/app/src/main/res/
├── mipmap-{m,h,x,xx,xxx}dpi/{ic_launcher,ic_launcher_round,ic_launcher_background}.png
├── mipmap-anydpi-v26/{ic_launcher,ic_launcher_round}.xml
├── drawable-nodpi/ic_launcher_foreground.png
└── drawable-xhdpi/tv_banner.png

parent/android/app/src/main/res/
├── mipmap-{m,h,x,xx,xxx}dpi/{ic_launcher,ic_launcher_round,ic_launcher_background}.png
└── mipmap-anydpi-v26/{ic_launcher,ic_launcher_round}.xml
```

## 7. 非功能要求

- **体积**：新增图标总量控制在 1 MB 以内。
- **观感**：外环不得被圆形/圆角遮罩切边；banner 文本在 320×180 下可读。
- **兼容**：Android 8.0 以下走传统 PNG；Android 8.0+ 走自适应图标；Android TV 走 banner。
- **可回滚**：纯资源与 manifest 属性改动，回退文件即可。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 自适应图标圆形遮罩切到外环 | 背景层 logo 缩至 96% 居中，外圈用底板色补齐 |
| 桌面启动器缓存旧图标 | 重装 APK；必要时清理 Launcher 缓存后复查 |
| TV banner 中文在 Leanback 上显示不全 | banner 使用两行短文本，生成后目视检查；不依赖系统字体粗细 |
| 传统图标在 Android 8+ 被套白底 | 同时提供 `mipmap-anydpi-v26`，系统优先使用自适应图标 |

## 10. 实施结果

- 孩子端与家长端 Android 均已接入官方亲子 logo；孩子端补充了 320×180 TV banner。
- 自适应图标采用「整张 logo 缩至 96% + 底板色补齐」，圆形遮罩下外环完整。
- 平板模拟器应用抽屉实测两端图标一致；家长端 iOS 图标未改动。
