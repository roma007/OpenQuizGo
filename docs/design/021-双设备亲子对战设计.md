## 1. 目标

在现有「同设备轮流」之外增加**双设备房间模式**：

- 家长设备创建房间，获得 6 位房间码；
- 孩子设备输入房间码加入；
- 孩子先答，家长设备轮询到轮次后作答；
- 双方看到同一组题与最终比分。

不引入 WebSocket；采用 2 秒轮询，保证单机/局域网可验收，后续可平滑替换为推送。

## 2. 状态机

```text
waiting ──join──▶ child_turn ──child submit──▶ parent_turn ──parent submit──▶ finished
```

- 同设备模式创建后直接 `child_turn`；
- 房间模式创建为 `waiting`，加入后进入 `child_turn`；
- 未加入时提交返回 409 `BATTLE_NOT_JOINED`；
- 加入幂等：同一房间重复加入直接返回当前状态。

## 3. 数据模型

```sql
alter table family_battle add column mode text not null default 'same_device'
  check (mode in ('same_device','room'));
alter table family_battle add column join_code text;
create unique index family_battle_join_code_idx
  on family_battle (join_code) where join_code is not null;
```

房间码由服务端生成（6 位，去掉易混淆字符），仅房间模式有值。

## 4. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/v1/family/children/{childID}/battles` | body 增加 `mode`（默认 `same_device`） |
| POST | `/v1/family/children/{childID}/battles/join` | `{code}` 加入房间 |
| GET | `/v1/family/children/{childID}/battles/{battleID}` | 增加 `mode`、`join_code` |

## 5. 前端流程

- 对战入口三个动作：`开始对战`（同设备）、`双设备房间`（创建）、`输入房间码`（加入）；
- 创建方：显示 6 位房间码 + 等待孩子加入 → 轮询 → 孩子答题中 → 轮到自己答题；
- 加入方：输入房间码 → 孩子答题 → 提交后等待家长答题 → 结果；
- 轮询间隔 2 秒，离开页面/进入结果页停止；
- 同一设备原流程保持不变。

## 6. 风险

| 风险 | 对策 |
| --- | --- |
| 房间码被猜中 | 6 位随机 + 仅家庭内孩子可用 + 家长令牌 |
| 轮询浪费请求 | 仅等待状态轮询，结束即停 |
| 重复加入/提交 | 状态机 + 幂等加入 + 轮次校验 |
| 网络中断 | 页面保留状态，恢复后重新拉取 |
| 单机验收限制 | 家长设备 UI 实测；孩子端用接口模拟 + Widget 测试 |
