## 1. 目标

让已上线的专题题包真正参与组卷：当存在匹配孩子学段/规则学科且在有效期内的在线专题时，优先从专题题目中抽题；没有匹配专题时保持原有组卷行为。

- 不修改 TV / 家长端协议，服务端自动生效；
- 管理端 `POST /v1/admin/quiz/preview` 可用于验证专题模式；
- 专题包题目不足 3 道时自动跳过，避免拖垮正常答题。

## 2. 匹配规则

一个专题包被启用需同时满足：

1. `status = online`；
2. 当前时间在 `[start_at, end_at]` 内（空表示不限）；
3. `stage_scope` 为空或包含孩子学段；
4. `subject_scope` 为空或与规则中正权重的学科有交集；
5. 该专题下在线且学段匹配的题目 ≥ 3 道。

多个专题同时匹配时，取 `updated_at` 最新的一个。

## 3. 抽题算法

- 题量 `n` 仍由规则 `SessionSize` 决定；
- 候选题来自 `topic_question` 关联的 `question`，仅 `online`、学段匹配；
- 先排除孩子近 30 天做过的题，按「学段接近 → 难度接近目标」排序后抽取；
- 不足时放宽最近 30 天限制，并标记 `repeated=true`；
- 仍不足时返回已抽到的题（≥3）并附 `topic_shortage` 警告；不足 3 道则回退普通组卷（启用检查已保证 ≥3）；
- 专题模式不再按学科配额分配，也不再校验加权门槛（专题是人工策划内容，避免权重不匹配导致 409）。

## 4. 接口与数据

不新增接口。组卷结果增加：

```json
{
  "topic_id": "...",
  "topic_name": "寒假数学闯关",
  "warnings": ["topic_mode:寒假数学闯关", "topic_shortage:寒假数学闯关"],
  "selected": [...]
}
```

`topic_id` / `topic_name` 为空表示普通组卷。

## 6. 风险

| 风险 | 对策 |
| --- | --- |
| 专题题目过少导致答题失败 | 少于 3 题不启用，直接回退 |
| 专题学科与规则不一致 | 启用要求学科交集；专题内允许跨学科 |
| 专题长期在线挤占常规题 | 专题有有效期，管理端可随时下线 |
| 孩子最近做过专题题 | 先排除近 30 天，不足再放宽并标记重复 |
