## 1. 背景与目标

### 1.1 现状与问题

- 家长端与服务器暂时不推进，TV 端现有流程依赖服务端：激活码绑定、创建答题会话、服务端判分、授权心跳、离线租约、家长远程解锁；
- 服务器和域名未准备，TV 安装后无法激活，整个守护流程不可用；
- 开发数据库中只有测试题（「导入题 1」「覆盖率测试」），没有可直接上线的真实题库；
- 现有 TV 端功能多（绑定、对战、诊断上传、会员），但当前阶段只需要「到时间弹一道题」。

### 1.2 本次目标（可验证）

1. TV 端完全离线可用：安装后不需要服务器、账号、家长端或网络。
2. 内置本地题库（≥100 道单选题），不按学龄/年级筛选，所有题目混合随机出题。
3. 首页只有一个业务开关：**定时答题**，默认开启。
4. 定时规则：累计视频播放满 **15 分钟** 自动弹出 1 道单选题；暂停播放、退出视频不计时。
5. 答对后继续观看；答错则保持答题界面，**直到答对**才可退出。
6. 关闭开关后不再弹出答题；重新开启后重新累计 15 分钟。
7. 重启电视/开机自启后开关状态保留，守护服务自动恢复。

### 1.3 非目标（明确不做什么）

- 家长端绑定、激活码、远程解锁、家庭 PIN；
- 服务端题库、答题会话、授权与心跳、离线租约、对战、会员；
- 学龄/年级/难度筛选、错题本、学习报告、数据上传；
- 在线更新题库（本期题库随 APK 打包，后续通过新版本替换）；
- iOS/Android 手机端。

## 2. 需求与验收标准

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| R1 | 离线可用 | 飞行模式、无网络、无服务器时，安装后即可进入首页并正常答题 | P0 |
| R2 | 本地题库 | APK 内置 `assets/questions.json`，≥100 道题，含题干、4 个选项、正确答案、解析 | P0 |
| R3 | 混合出题 | 出题不读取学龄/年级，所有题目等概率随机；连续两轮不重复同一题 | P0 |
| R4 | 15 分钟计时 | 仅媒体播放时累计，满 900 秒触发；暂停/退出不累计 | P0 |
| R5 | 开关 | 首页提供「定时答题」开关，默认开启；关闭后不触发 | P0 |
| R6 | 答对继续 | 答对显示正确反馈，点击「继续观看」退出答题并重新计时 | P0 |
| R7 | 答错锁定 | 答错停留原题，返回键无效，直到答对 | P0 |
| R8 | 自动弹出 | 到点后自动全屏弹出答题界面；被切走/关闭时守护服务自动重新拉起 | P0 |
| R9 | 开机自启 | 重启后服务恢复，开关与计时状态合理恢复 | P1 |
| R10 | 质量门禁 | 单元测试通过，Debug/Release 构建通过，真机/模拟器可验收 | P0 |

## 3. 方案对比与选型

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 保留服务端模式，增加离线缓存 | 改动小 | 仍需激活与服务器，违背本期目标 | 否决 |
| B. 新增「本地模式」分支，保留服务端代码 | 可随时切回 | 两套状态机并存，复杂且易误触网络 | 否决 |
| C. 删除服务端耦合，TV 改为纯本地单机应用 | 架构最简单，安装即用 | 需要重写状态机/答题界面并清理旧模块 | **采用** |
| D. 单独新建 TV 工程 | 隔离彻底 | 复制权限/无障碍/媒体检测等成熟代码，维护两份 | 否决 |

选型理由：当前阶段产品边界已经收敛为「本地题库 + 定时答题」，方案 C 可以显著降低运行复杂度和故障面；旧服务端代码保留在 Git 历史中，后续需要时再恢复。

## 4. 总体架构

### 4.1 模块划分

| 模块 | 职责 |
| --- | --- |
| `data/local/LocalSettings` | DataStore 保存「定时答题」开关，默认开启 |
| `data/local/QuestionBank` | 读取并解析 `assets/questions.json`，随机取题 |
| `data/foreground/MediaPlaybackDetector` | 通过 `AudioManager` 判断媒体是否在播放 |
| `domain/LocalGuardEngine` | 计时与状态机：空闲/观看/待答题/答题中/通过 |
| `platform/GuardService` | 前台服务、通知、看门狗、到点拉起答题 |
| `platform/GuardAccessibilityService` | 无障碍事件 + 自动拉起答题（后台启动 Activity 的可靠通道） |
| `ui/MainActivity` | 首页：开关、状态、倒计时、权限入口 |
| `ui/QuizActivity` | 单题答题、答错重试、答对退出 |

### 4.2 状态机

```text
IDLE（开关关闭 / 未播放）
   │
   ├── 开关开启且媒体播放 ──> WATCHING ──累计 900s──> QUIZ_REQUIRED
   │                            ▲                         │
   │                            │                    拉起答题界面
   │                            │                         ▼
   │                            └───答对/计时清零──── QUIZZING
   │                                                       │
   └── 开关关闭 <──────────────────────────────────────────┘
                                                       答错：停留本题
```

- `IDLE`：开关关闭，或开关开启但当前没有媒体播放；不计时、不弹题；
- `WATCHING`：开关开启且媒体播放中，按秒累计；
- `QUIZ_REQUIRED`：累计满 900 秒，等待答题界面展示；
- `QUIZZING`：答题界面已展示，计时暂停；
- `GRANTED`：答对后的短暂状态，随后回到 `WATCHING`；
- 答对后把累计秒数清零；答错保持 `QUIZZING`，直到答对。

### 4.3 触发流程

```text
MediaPlaybackDetector(mediaActive=true)
        │ 每秒
        ▼
LocalGuardEngine 累计 +1s
        │ ≥900s
        ▼
QUIZ_REQUIRED
        │
GuardService 观察到状态 → GuardAccessibilityService.launchQuiz()
        │
        ▼
QuizActivity（全屏，播放器失焦暂停）
        │
   答对 ──> engine.onPassed() ──> 计时清零 ──> 退出答题
        │
   答错 ──> 停留本题，返回键无效
```

看门狗每 2 秒检查：若状态为 `QUIZ_REQUIRED`/`QUIZZING` 且答题界面不在前台，则重新拉起。

### 4.4 启动与常驻

- 首次安装后，Android 会把新应用置为 **stopped 状态**，此时不会接收开机广播；
  必须至少启动一次应用（或通过 `adb` 显式启动组件），这是系统限制，App 无法绕过。
- 首次启动会拉起 `GuardService` 前台服务，随后按 Home 键即可退到后台；之后不再需要打开主界面。
- 开机自启由 `BootReceiver` 负责，监听：
  - `BOOT_COMPLETED`
  - `QUICKBOOT_POWERON` / `com.htc.intent.action.QUICKBOOT_POWERON`（部分电视的快速开机广播）
  - `MY_PACKAGE_REPLACED`（APK 升级后）
- 后台常驻由前台服务 + `START_STICKY` 保证；系统会显示一条低优先级常驻通知，这是 Android 的要求。
- `MainActivity` 只在用户点击桌面图标时显示设置开关；到点答题只显示全屏 `QuizActivity`，答完即退出。
- 提供 `tv/scripts/install_and_start.sh`：安装 → 通过无界面 `BootstrapActivity` 启动服务（不显示前端），可选通过 adb 开启无障碍服务。
- 默认开关为开启；用户关闭后保持关闭，直到手动打开。

### 4.5 断点与常量

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `QUIZ_INTERVAL_SECONDS` | 900 | 每累计播放 15 分钟出 1 题 |
| `QUESTIONS_PER_ROUND` | 1 | 每轮 1 题 |
| `WATCHDOG_INTERVAL_MS` | 2000 | 答题界面丢失时重新拉起 |
| `RELATIVE_RETRY` | 无 | 答错只重试当前题，不换题 |

## 5. 数据模型

### 5.1 本地题库 JSON

`tv/app/src/main/assets/questions.json`：

```json
{
  "version": 1,
  "generated_at": "2026-11-12",
  "questions": [
    {
      "id": "m001",
      "subject": "math",
      "stage": "low",
      "difficulty": 1,
      "stem": "3 + 5 = ?",
      "options": [
        {"id": "a", "text": "7"},
        {"id": "b", "text": "8"},
        {"id": "c", "text": "9"},
        {"id": "d", "text": "10"}
      ],
      "answer": "b",
      "explain": "3 + 5 = 8"
    }
  ]
}
```

约束：

- `options` 固定 4 项，`id` 为 a/b/c/d，文本非空且不重复；
- `answer` 必须等于其中一个选项 id；
- `id` 全局唯一；
- `stage` 仅作标签，本期选题不使用；`subject` 用于后续统计扩展；
- 解析失败时题库为空，首页提示「题库加载失败」，不得崩溃。

### 5.2 本地设置

DataStore（`local_guard`）：

| Key | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `quiz_enabled` | Boolean | `true` | 定时答题开关 |
| `elapsed_seconds` | Long | `0` | 已累计播放秒数（进程重启后可恢复） |
| `last_question_id` | String? | `null` | 避免连续两轮同一题 |

## 6. 接口设计

不涉及 HTTP。内部接口：

| 类型 | 名称 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- | --- |
| Kotlin | `QuestionBank.random(excludeId)` | `String?` | `LocalQuestion?` | 随机取题，排除上一题 |
| Kotlin | `LocalGuardEngine.setEnabled` | `Boolean` | Unit | 开关 |
| Kotlin | `LocalGuardEngine.onQuizStarted` | — | Unit | 进入答题中 |
| Kotlin | `LocalGuardEngine.onQuizPassed` | — | Unit | 答对，计时清零 |
| Flow | `LocalGuardEngine.state` | — | `LocalGuardState` | 首页/服务观察 |
| StateFlow | `LocalGuardEngine.remainingSeconds` | — | `Long` | 首页倒计时 |

## 7. 非功能要求

- 性能：计时器 1 秒一次轻量协程；题库只在启动时解析一次（约 100KB）。
- 电量：媒体检测 2 秒轮询 + 前台服务通知，保持现有水平。
- 离线：无任何网络请求；删除 `INTERNET` 权限。
- 可靠性：答题界面丢失由看门狗重新拉起；服务被系统杀死后 `START_STICKY` + 开机广播恢复。
- 可维护性：题库 JSON 可独立替换；新增题目无需改代码。
- 兼容性：沿用现有 minSdk 26 / targetSdk 33 与电视遥控器操作。

## 8. 风险与对策

| 风险 | 影响 | 概率 | 对策 |
| --- | --- | --- | --- |
| 后台启动 Activity 被系统拦截 | 到点不弹题 | 中 | 通过无障碍服务拉起；看门狗重试；首页提示开启无障碍 |
| 部分播放器静音/无音频时 `isMusicActive=false` | 不计时 | 中 | 以 `mediaActive` 为准；后续可补前台包名白名单 |
| 孩子反复试错直到答对 | 轻松绕过 | 高 | 本期接受；后续可加错题冷却/换题 |
| 题库内容质量 | 学习效果 | 中 | 内置题目标注解析；后续人工校对与替换 |
| 答题界面被 Home 键切走 | 继续观看 | 中 | 看门狗每 2 秒重新拉起 |
| 15 分钟计时在服务重启后丢失 | 计时重置 | 低 | 累计秒数持久化，启动恢复 |
