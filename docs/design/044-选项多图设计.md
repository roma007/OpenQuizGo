## 1. 目标

在保持 040 单图兼容的前提下，允许一个选项最多 3 张图片：

- 选项 JSON 增加可选 `images: string[]`；
- 旧 `image: string` 继续有效，读取时合并；
- 管理端可为一个选项上传多张图片并逐张移除；
- TV 选项按钮最多渲染 3 张缩略图。

## 2. 数据

```json
{"id":"a","text":"","image":"/v1/media/a.png","images":["/v1/media/a.png","/v1/media/b.png"]}
```

- 服务端仍存 raw JSON，无迁移；
- 校验：`id` 非空且唯一；`text`、`image`、`images` 至少一个有效；`images` 最多 3 项，每项非空；
- 为兼容旧数据，保存时可只写 `images`，读取端同时接受 `image`。

## 3. 前端与 TV

- 管理端 `OptionItem` 增加 `images?: string[]`；上传后追加，移除单张；旧 `image` 自动并入展示；
- 保存时统一写 `images`（同时保留首图到 `image` 以兼容旧 TV 版本）；
- TV `QuizOption` 增加 `images: List<String>?`，优先渲染 `images`，否则回退 `image`；
- TV 用 `Row` 渲染，最多 3 张，单张最大高度 90dp。

## 4. 风险

| 风险 | 对策 |
| --- | --- |
| 旧客户端不识别 images | 继续写 `image` 首图 |
| 图片过多占满屏幕 | 服务端限 3 张，TV 限高 |
| 空 URL | 服务端过滤并校验 |
