## 1. 目标

让会员权益从“展示文字”变成可执行的开关。本期先落地两项：

1. **付费专题题包**：`is_paid = true` 的专题，只有家庭内存在有效会员且套餐包含 `topic_pack` 权益时才会参与组卷；
2. **进阶报告**：套餐包含 `report_advanced` 权益时，家长端在报告中看到进阶分析区块；否则显示开通提示。

同时把套餐权益改为结构化代码，管理端可配置，家长端展示。

## 2. 权益代码

| code | 名称 | 作用 |
| --- | --- | --- |
| `topic_pack` | 付费专题题包 | 允许付费专题参与组卷 |
| `report_advanced` | 进阶报告 | 解锁报告页进阶分析 |
| `customer_service` | 专属客服 | 仅展示，暂不控制功能 |

套餐可同时包含多个代码；`features` 继续作为展示文案保留。

## 3. 数据模型

```sql
alter table membership_plan
  add column entitlement_codes jsonb not null default '[]'::jsonb
  check (jsonb_typeof(entitlement_codes) = 'array');
```

种子月卡/年卡回填 `["topic_pack","report_advanced"]`。

## 4. 判定规则

- 家庭会员：孩子所属家庭内任一家长账号存在 `status = active` 且 `expires_at > now()` 的会员；
- 套餐包含对应权益代码才生效；
- 会员到期后权益立即失效；
- 付费专题在无权益时被跳过，不影响免费专题与普通组卷；
- 组卷预览未指定孩子时无法判定家庭，付费专题不参与预览。

## 5. 接口变化

- `GET /v1/family/membership`：`membership.entitlements` 返回当前有效权益代码数组；
- `GET/POST/PUT /v1/admin/membership/plans`：增加 `entitlement_codes`；
- 组卷接口无协议变化，仅内部过滤。

## 6. 前端

- 管理端套餐弹窗增加「功能权益」多选；
- 家长端会员中心显示权益标签；
- 报告页新增「进阶分析」卡片：
  - 有权益：薄弱学科、近 7 天趋势、建议练习方向；
  - 无权益：锁定样式 + 「会员权益」提示。

## 7. 风险

| 风险 | 对策 |
| --- | --- |
| 权益代码拼写错误 | 服务端固定白名单校验 |
| 到期后缓存仍生效 | 每次查询实时判断 `expires_at` |
| 付费专题被误用 | 组卷 SQL 内联会员判定，不依赖前端 |
| 进阶分析数据不准确 | 仅基于现有报告数据做聚合，不新增推断 |
