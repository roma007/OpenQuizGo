## 1. 背景

恢复出厂或卸载后设备无法主动解绑，服务端 `device_bind` 会残留 active 记录。通过记录设备最近活跃时间，定期解绑长期无活动设备。

## 2. 数据

`device_bind.last_seen_at timestamptz not null default now()`。

- 设备鉴权成功时刷新；
- 条件更新：距上次记录超过 5 分钟才写，降低写放大；
- 现有 active 绑定初始化为迁移时间。

## 3. 自动解绑

- 配置 `DEVICE_STALE_DAYS` 默认 30，0 表示关闭；
- worker 每个报告周期执行一次；
- 解绑 `status='active' and last_seen_at < now() - N days` 的设备；
- 清空 token，置 unbound。

## 4. 风险

| 风险 | 对策 |
| --- | --- |
| 长期关机误解绑 | 默认 30 天，可配置/关闭 |
| 写放大 | 5 分钟节流 |
| 误伤 | 只处理 active，令牌立即失效可重新绑定 |

## 5. 限制

- 不是恢复出厂即时感知，而是最长 N 天后清理；
- 不做设备指纹；
- 解绑不撤销已签发授权。
