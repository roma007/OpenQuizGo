## 1. 目标

支付渠道完成退款后，可通过 HMAC 签名回调通知服务端，服务端执行与后台退款一致的会员回退，并记录渠道退款单号；重复回调幂等。

## 2. 接口

`POST /v1/payments/refund-callback`

Header：`X-Payment-Signature: hex(HMAC-SHA256(body, secret))`

```json
{"order_no":"M...","refund_no":"R...","status":"refunded","reason":"用户申请"}
```

- `REFUND_CALLBACK_SECRET`，未配置时回退 `PAYMENT_CALLBACK_SECRET`；都为空则 503；
- 仅 `status=refunded`；
- 按 `order_no` 查订单；已退款直接返回（幂等）；
- 记录 `external_refund_no`，用于渠道对账。

## 3. 退款处理

- 复用内部退款逻辑：回退会员到期时间、写退款快照、归还优惠券次数；
- 退款原因默认「渠道退款」，最多 200 字；
- 回调不要求管理员身份。

## 4. 风险

| 风险 | 对策 |
| --- | --- |
| 伪造回调 | HMAC 常量时间比较 |
| 重复回调 | 已退款直接返回，不重复回退 |
| 并发回调 | 订单行锁 |
| 渠道单号冲突 | 唯一索引 |
