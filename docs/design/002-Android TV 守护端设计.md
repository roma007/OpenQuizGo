## 1. 背景与目标

### 1.1 背景

第一期服务端已交付（v0.1.0）。T0 在创维 3T223_P31（Android 9）上的实测结论：

- 悬浮窗被系统白名单拦截，无法覆盖视频；
- 播放器不暴露 MediaSession，忽略音频焦点与媒体键；
- 播放器画面不在无障碍节点树，无法点击暂停；
- 第三方视频 App 侧载被拦截，只能使用商店/预装应用；
- **全屏 Activity 接管可用**：拉起后播放器停止，退出后进度保留、续播，但会重播一次片头广告；
- HOME 逃逸可由无障碍看门狗重新拉起（实测约 0.5s）。

### 1.2 目标

交付可安装、可运营的 Android TV 守护端，实现：

1. 设备激活与家庭绑定；
2. 前台应用识别与观看计时；
3. 到点/额度用尽时全屏接管，完成答题后恢复播放；
4. 与服务端授权、心跳、离线租约、报告体系联动；
5. 家长可配置规则、查看状态，孩子无法轻易绕过。

### 1.3 非目标

- 不做视频内容播放器（观看第三方 App）；
- 不做家长端 App（003 设计）；
- 不做题库后台 UI（第三期）；
- 不承诺管控 HDMI、投屏、其他设备。

## 2. 关键决策

| 决策 | 结论 | 依据 |
| --- | --- | --- |
| 暂停/接管方式 | **全屏 Activity 优先**；MediaSession 暂停仅作支持机型增强 | 创维实测 |
| 前台识别 | AccessibilityService 事件 + UsageStats 兜底 | 创维可用 |
| 防逃逸 | 无障碍看门狗：非允许应用前台时重新拉起阻挡界面 | 实测 0.5s |
| 广告代价 | 创维接管后恢复会重播片头广告，**接受**；后续靠厂商/白名单消除 | 产品决策 |
| 第三方 App | 只用商店/预装应用；不做侧载引导 | 创维拦截 |
| 权限最小化 | 使用情况访问 + 无障碍为主；悬浮窗/通知使用权可选 | 合规 |
| 技术栈 | Kotlin + Jetpack Compose for TV + Coroutines/Flow | 001 设计 |
| 包名 | `com.openquizgo.quiz`（namespace `com.openquizgo.guard`） | 创维拦截 `guard`/`tv` 包名，实测 `quiz` 可安装 |
| 最低系统 | Android TV 9（API 28） | 创维实测 |

## 3. 总体架构

```
┌─────────────────────────────────────────────┐
│                TV 守护端 App                 │
│                                             │
│  UI 层        Activation / Home / Quiz      │
│               Blocker / PermissionGuide     │
│                                             │
│  领域层       GuardEngine（状态机/触发）      │
│               QuizFlow / WatchFlow          │
│               PolicyEvaluator（本地缓存）     │
│                                             │
│  平台层       ForegroundDetector             │
│               PlaybackController            │
│               DeviceSecurity（Keystore）     │
│               OfflineStore（DataStore/Room） │
│               ApiClient / HeartbeatWorker   │
│                                             │
│  系统能力     AccessibilityService           │
│               UsageStatsManager              │
│               ForegroundService              │
│               BootReceiver                   │
└─────────────────────────────────────────────┘
```

### 3.1 模块职责

| 模块 | 职责 |
| --- | --- |
| `GuardEngine` | 守护状态机、触发答题/阻挡、看门狗、与播放控制协同 |
| `ForegroundDetector` | 前台包名、媒体播放状态、使用时长 |
| `PlaybackController` | 优先 MediaSession 暂停/恢复；不可用时 Activity 接管 |
| `QuizFlow` | 创建会话、拉题、提交、结算、展示解析 |
| `WatchFlow` | 授权查询、心跳、暂停不计量、离线租约与补报 |
| `PolicyEvaluator` | 使用服务端规则快照做本地预判（最终以服务端为准） |
| `OfflineStore` | 设备令牌、规则快照、离线租约、待上报队列 |
| `DeviceSecurity` | Keystore 令牌、设备指纹、时钟校验、完整性检测 |
| `Diagnostics` | 日志、能力上报、篡改事件、崩溃上报 |

## 4. 状态机

```
UNBOUND ──激活──> IDLE
IDLE ──检测到视频前台──> WATCHING
WATCHING ──额度耗尽/到答题点──> QUIZ_REQUIRED
QUIZ_REQUIRED ──拉起答题──> QUIZZING
QUIZZING ──通过──> GRANTED
QUIZZING ──失败/超时──> BLOCKED
GRANTED ──继续观看/心跳──> WATCHING
GRANTED ──授权到期──> QUIZ_REQUIRED
BLOCKED ──家长解锁/重新答题──> QUIZZING
任意 ──解绑/停用──> UNBOUND
```

关键规则：

- 状态持久化，进程重启/电视待机后恢复；
- 答题期间强制心跳 `paused=true`，服务端不计量；
- 阻挡状态下检测到非允许应用前台，看门狗重新拉起；
- 家长端解绑后立即清理令牌与本地状态。

## 5. 前台识别与观看计时

### 5.1 识别

- AccessibilityService 监听 `TYPE_WINDOW_STATE_CHANGED`，记录前台包名；
- 每 30s 采样 `UsageStatsManager` 校正；
- 播放状态优先用 `MediaSessionManager`（若可用）；不可用时以「前台应用 + 音频播放中」判断；
- 使用 `scope_mode`：
  - `media`：检测到媒体播放才计时/管控；
  - `custom`：仅清单内应用；
  - `all_apps`：除系统白名单外全部管控。

### 5.2 计时

- 本地按 30s 心跳上报，服务端按间隔计费；
- 答题/阻挡期间暂停计时；
- 断网时进入离线模式，使用租约并本地累计，恢复后补报；
- 时钟异常（与服务端偏差 >5 分钟）上报 `clock_skew` 并限制解锁。

## 6. 接管与暂停策略

按优先级尝试：

| 优先级 | 手段 | 适用 | 说明 |
| --- | --- | --- | --- |
| 1 | MediaSession `pause()/play()` | 播放器暴露 MediaSession | 保留进度，无广告 |
| 2 | 音频焦点 | 播放器响应焦点 | 部分机型 |
| 3 | 媒体键 | 有媒体会话 | 兼容性兜底 |
| 4 | **确认键暂停 + 半透明答题** | 创维等按键可过滤机型 | **首选**：用户按 OK 暂停，App 监听按键后弹半透明答题；退出再按 OK 续播；无广告、进度不丢 |
| 5 | 全屏 Activity 接管 | 无法按键过滤/超时兜底 | 停止播放器，进度保留；可能重播片头广告 |
| 5 | 悬浮窗遮罩 | 未被白名单拦截的机型 | Android 10+ 需额外验证 |

- 生产默认顺序：检测能力后动态选择；创维走「确认键暂停 + 半透明答题」（实测 2026-11-03）。
- 接管时记录 `was_playing`、前台包名、进入时间；
- 退出后：若播放器自动续播则直接恢复；若停在首页/广告，展示「继续观看」提示，不自动跳转；
- 广告重播：已知限制，文案提示「恢复播放时可能出现片头广告」。
- 2026-11-03 补充实测：即使先用确认键暂停、再打开答题 Activity，退出后仍会重播广告；广告由播放器 Activity 重启触发。应用无法注入确认键（`INJECT_EVENTS` 签名权限），因此标准模式无法同时满足「暂停 + 保留进度 + 无广告」。

## 7. 答题流程

```
ForegroundDetector 发现视频播放
  -> GuardEngine 拉取 /child/context
  -> 需要答题：Toast/TTS 提示「按确认键开始答题」，进入 armed 状态
  -> 用户按 OK：播放器自身暂停（不重启，无广告）
  -> AccessibilityService 监听按键（不消费），延迟 ~600ms
  -> 拉起半透明 QuizActivity（玩家 Activity 不被 stop，保持 paused）
  -> POST /quiz/sessions -> 答题 -> /answers -> /finish
  -> 通过：退出答题，提示「按确认键继续观看」
  -> 用户按 OK：播放器恢复，进度保留
  -> 超时未按键/不支持按键：回退到全屏 Activity 接管（可能重播广告）
```

- 题目与选项大字、焦点清晰；低龄支持图片/语音；
- 单题限时与服务端一致；
- 断网时不允许答题解锁，只展示离线说明。

## 8. 授权、心跳与离线

- 启动/唤醒：`GET /watch/grants/active`；
- 心跳：30s，携带 `foreground_app`、`paused`、`position_seconds`；
- 授权到期/吊销：立即拉起阻挡界面；
- 离线：预取 `/offline/lease`，本地验签 Ed25519；播放时长本地累计，恢复后 `/watch/logs` 对账；
- 离线期间不产生新的答题解锁；
- 所有时间以服务端返回的 `server_time` 校正。

## 9. 权限与引导

| 权限 | 必需 | 用途 | 失败处理 |
| --- | --- | --- | --- |
| 无障碍 | 是 | 前台识别、看门狗 | 引导开启，未开启进入受限模式 |
| 使用情况访问 | 是 | 计时校正 | 引导开启 |
| 悬浮窗 | 否 | 部分机型遮罩 | 创维不需要 |
| 通知使用权 | 否 | MediaSession | 无则走 Activity 接管 |
| 前台服务/自启 | 是 | 守护常驻 | 引导电池优化白名单 |
| 安装未知应用 | 否 | 仅内测 | 商店安装 |

首次启动流程：激活码 → 家长绑定 → 权限逐项引导 → 自检 → 进入守护。

## 10. 防绕过

| 场景 | 处理 |
| --- | --- |
| 按 HOME | 看门狗 1s 内重新拉起阻挡 |
| 切换其他 App | 拦截模式重新拉起；允许应用放行 |
| 重启电视 | BootReceiver 启动守护，恢复状态 |
| 关闭无障碍 | 检测并上报 `permission_revoked`，家长端告警 |
| 卸载 | Device Owner 模式禁止；标准模式检测 |
| 改系统时间 | 服务端时间校正，偏差过大限制 |
| 断网 | 离线租约限时，恢复对账 |
| HDMI/投屏 | 明确不支持，协议声明 |

## 11. 非功能

- 启动 ≤3s；守护内存 ≤150MB；心跳耗电可接受；
- 崩溃自动重启守护；关键路径本地日志；
- 隐私：只采集包名/时长/授权状态，不采集画面与内容；
- 合规：家长同意、儿童数据最小化、可注销。

| 维度 | 覆盖 |

验收口径（暂定）：

- 接管到画面消失 ≤1s；
- 退出后进度保留率 100%（创维实测通过）；
- 看门狗重新拉起 ≤2s；
- 广告重播作为已知机型限制记录，不计失败。

## 13. 风险与未决问题

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Android 10+ 后台 Activity 启动受限 | 接管失败 | 逐机型验证；必要时 Device Owner/悬浮窗 |
| 恢复时重播广告 | 体验 | 接受；厂商白名单/预装消除 |
| 第三方 App 侧载被拦截 | 只能商店安装 | 引导商店安装；厂商合作 |
| 播放器不自动续播 | 需手动继续 | 文案提示 + 恢复按钮 |
| 无障碍被关闭 | 管控失效 | 检测+告警+引导 |
| 按键过滤在部分机型不可用 | 无法实现无广告暂停 | 逐机型验证；回退全屏接管 |
| 用户不按确认键/超时 | 答题无法开始 | 提示 + 超时回退（接受广告） |
| 语音答题 ASR 成本 | 低龄体验 | 二期先点选，语音后续 |

未决：

- 是否申请 Device Owner 作为增强模式？
- 家长端解锁（临时密码/远程放行）如何设计？
- 广告是否可在恢复时通过播放器历史跳过？
- 多用户/儿童模式与系统账号的关系？
