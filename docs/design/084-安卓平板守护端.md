## 1. 背景与目标

### 现状与问题

现在被管控设备只有电视端（`tv/`，Android TV 专用）。实际家庭里孩子经常直接用**安卓平板**看视频，电视端装在平板上不可用：

| 现状 | 在平板上的后果 |
| --- | --- |
| `android.software.leanback required="true"` | 应用商店判定为「仅电视」，平板搜不到 |
| 只注册 `LEANBACK_LAUNCHER` | 平板桌面没有图标，只能靠数据线/第三方启动器打开 |
| `android:screenOrientation="landscape"` 锁横屏 | 平板竖握时也是横屏，且部分平板会黑边 |
| UI 全部用 `androidx.tv.material3` + 遥控器焦点交互 | 手指点不动、没有可输入的键盘框，登录页靠数字键 `dispatchKeyEvent` |
| 登录页依赖遥控器数字键 | 平板上完全无法输入手机号/验证码 |

管控能力本身在安卓平板上是成立的：前台应用识别（`UsageStatsManager`）、无障碍拦截（`AccessibilityService`）、全屏答题接管（`startActivity`）在平板上行为与电视一致，核心引擎 `domain/GuardEngine.kt`（766 行）与 `platform/*` 与设备形态无关，可直接复用。

### 本次目标

- G1 孩子使用的**安卓平板**可以安装同一个守护端 App，并用触摸正常使用全部流程（登录、看状态、答题、被拦截）。
- G2 电视端体验**不回归**：创维电视上的遥控器操作、全屏答题、硬停页面保持现有行为。
- G3 设备类型进入服务端：电视登记为 `tv`，平板登记为 `pad`；家长端能区分并显示。
- G4 只发一个安装包（同一 `applicationId`、同一版本号），减少分发与版本漂移。
- G5 首次安装有清晰的权限与受限设置引导（平板用户是自己点着装的，不像电视有装机人员）。

### 非目标

- **不支持 iPad**（见附录 A：苹果平台限制，无法做「答对才能看」的接管）。
- 不做平板上的「多窗口/分屏」特殊适配（按全屏使用设计）。
- 不做家长端平板布局改造（076 已覆盖家长端 iPad/平板适配）。
- 不做应用商店上架（仍为内部分发 APK）。
- 不做「设备所有者（Device Owner）」强制托管（见 11 未决问题）。

## 2. 需求与验收标准

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| R1 | 平板可安装 | 平板桌面出现「OpenQuizGo 守护端」图标，点击可启动 | P0 |
| R2 | 触摸登录 | 平板登录页可用软键盘输入手机号/验证码并登录成功 | P0 |
| R3 | 触摸答题 | 全屏答题页可用手指选择选项、提交；填空/语音题可输入 | P0 |
| R4 | 拦截生效 | 平板打开被管控视频 App 后被拦截并弹出答题页 | P0 |
| R5 | 电视不回归 | 电视上遥控器操作、答题、硬停、连按 5 次诊断全部照旧 | P0 |
| R6 | 设备类型 | 平板登录后服务端 `tv_device.platform='pad'`，家长端显示「平板」 | P1 |
| R7 | 竖屏可用 | 平板竖屏/横屏切换时界面不破版（无遮挡、无需重启） | P1 |
| R8 | 权限引导 | 平板首次进入能看到「无障碍 / 使用情况」两步引导，含 Android 13+ 受限设置说明 | P1 |
| R9 | 同一套规则 | 平板与电视共用 082/083 的题量、答对题数、放行时长语义 | P0 |

## 3. 方案对比与选型

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A 单包运行时切换 | 同一个 `tv/` 模块，新增 `ui/pad/` 触摸界面；启动时按设备形态选择 UI | 一个 APK、一套版本、一份规则；共享 `domain`/`data`/`platform`；风险集中在 UI 层 | APK 内含两套 UI 代码（约 +1.5k 行）；`tv-material` 与 `material3` 并存 | **采用** |
| B 独立 pad 模块 | 抽 `:core` 库模块，新建 `:pad` app 模块 | 依赖干净，可裁剪体积 | 需搬 2000+ 行代码与包名、双版本号、双发版流程，回归面大 | 不采用（二期可演进） |
| C 现有 UI 改通用 | 把 6 个 Activity 就地改成 `material3` + 焦点/触摸双适配 | 无重复代码 | 直接动已在线验证的电视界面，回归风险最高；电视焦点效果要自己重写 | 不采用 |

选 A：**电视界面一行不改**，新增一套触摸界面，运行时二分。

## 4. 总体架构

```
                    ┌──────────────────────────────┐
                    │ app 启动（MainActivity/Bootstrap）│
                    └───────────────┬──────────────┘
                                    │ FormFactor.detect()
                    ┌───────────────┴───────────────┐
                    │                               │
         IsTelevision（UiMode + FEATURE_LEANBACK）   其他（pad / phone）
                    │                               │
        ui/tv/*（现状，tv-material）          ui/pad/*（新增，material3 + 触摸）
                    └───────────────┬───────────────┘
                                    │
                       共享：GuardViewModel / GuardEngine
                             data/*（Retrofit、DataStore）
                             platform/*（无障碍、前台识别、前台服务）
                                    │
                                    ▼
                         服务端 /v1/tv/*、/v1/quiz/*
```

要点：

1. **形态判定只做一次**，结果放 `FormFactor` 单例（`object` + `Context` 扩展），供 Activity 与 Compose 共用。
2. **界面切换用 Activity 层**：`MainActivity` 里 `setContent` 前判断，电视走 `GuardScreen`（现有），平板走 `PadGuardScreen`（新增）；答题、拦截、硬停同理。
3. **共享 ViewModel 与状态机**：不加第二套业务状态，平板界面只消费 `GuardUiState` / `QuizRepository`，避免两套逻辑分叉。
4. **不做 manifest 双入口**：仍只有一个 `MainActivity`，同时注册 `LAUNCHER` 与 `LEANBACK_LAUNCHER` 两个 category。

## 5. 与电视端的差异清单

| 项 | 电视（现状） | 平板（新增） |
| --- | --- | --- |
| manifest 启动入口 | 仅 `LEANBACK_LAUNCHER` | 增加 `LAUNCHER` |
| `leanback` 特性 | `required="true"` | 改为 `required="false"`（电视商店可见性靠 category 判断） |
| 屏幕方向 | `screenOrientation="landscape"` | 去掉锁屏方向，跟随系统 |
| 主题组件库 | `androidx.tv.material3` | `androidx.compose.material3` |
| 登录输入 | 遥控器数字键 `dispatchKeyEvent` | 文字输入框 + 软键盘，保留数字键分支 |
| 答题交互 | D-pad 焦点 + 确认键 | 触摸点击大按钮，选中高亮 |
| 字体/间距 | 3 米观看距离，大字号 | 手持距离，常规字号 + 触摸目标 ≥ 48dp |
| 诊断入口 | 连按 5 次确认键 | 主页右上角 5 次点击「版本号」 |
| 权限引导 | 自检页（`SelfCheckActivity`） | 同样的检查项，触摸版引导 + 跳转按钮 |
| 设备类型上报 | `platform` 省略（服务端默认 `tv`） | `platform: "pad"` |

## 6. 数据模型与接口

### 6.1 数据库

无需迁移：`tv_device.platform` 在 00033 已允许 `('tv','pad')`；`tv_config`、`watch_rule` 与设备形态无关。

### 6.2 接口

仅一处扩展，向后兼容：

- `POST /v1/tv/login` 入参新增可选 `platform`（`tv` | `pad`，缺省 `tv`，非法值 422）。
- `TVDevice` 响应新增 `platform`，家长端设备列表可见。
- 其余（`/v1/tv/context`、`/v1/quiz/*`、`/v1/rule/*`）不变。

```jsonc
// POST /v1/tv/login
{ "phone": "138...", "code": "123456", "device_id": "...", "device_name": "小米平板", "platform": "pad" }
```

### 6.3 家长端

- `TvDevice` 增加 `platform`。
- 设备列表、设备详情标题按类型显示「电视」/「平板」；同一条规则页文案改为「设备」（不再固定写「电视」）。

## 7. 平板界面清单

| 界面 | 复用 | 说明 |
| --- | --- | --- |
| 登录 | `GuardViewModel` 登录逻辑 | 手机号 + 验证码输入框，倒计时、错误提示 |
| 主页 | `GuardUiState.Ready` | 设备名、孩子、今日已看/剩余、下次答题时间；「开始答题」「立即解锁」按钮 |
| 答题页 | `QuizRepository`、判分接口 | 全屏、进度、题面/图片、选项大按钮、提交与结果、通过/未通过 |
| 拦截页 | `GuardEngine` 触发 | 「时间到了/需要答题才能继续看」+ 两个按钮（答题 / 结束） |
| 硬停页 | `HardStopActivity` 语义 | 今日额度用完提示，倒计时显示 |
| 权限引导 | `Permissions` | 无障碍、使用情况统计、通知；含 Android 13+「受限设置」放开步骤 |
| 诊断 | `LogExporter` | 隐藏入口，导出日志文件 |

## 8. 权限与安装引导（平板特有）

1. 安装 APK 后首次打开：显示 3 步引导（无障碍 → 使用情况统计 → 通知），每步一个「去设置」按钮，返回后自动刷新状态。
2. Android 13/14 从浏览器/文件管理器侧载的 APK，无障碍开关会被「受限设置」拦住：引导页文案写清「应用信息 → 右上角三点 → 允许受限设置」。
3. 部分国产 ROM（MIUI/HyperOS、ColorOS、HarmonyOS）需要额外「自启动」「后台运行」白名单，引导页给一句通用提示，不逐个机型适配。
4. 平板锁屏/息屏后前台服务可能被系统回收，靠现有 `BootReceiver` + 前台服务恢复；引导页说明「不要清理后台」。

## 9. 非功能要求

- 性能：平板界面首帧 < 1s；答题页切换 < 200ms；不与电视共用进程状态，避免互相影响。
- 体积：单包 APK 预计增加 < 1MB（material3 已随 compose 传递依赖）。
- 兼容：`minSdk 26`、`targetSdk 33` 不变；重点验证 Android 10/12/13/14 平板。
- 可维护：平板界面不得复制业务逻辑，只允许调用共享 ViewModel/Repository。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 改动 manifest 影响电视启动 | 电视桌面无图标 | `LAUNCHER` 与 `LEANBACK_LAUNCHER` 并存；真机回归创维 |
| `leanback required=false` 后电视商店筛选变化 | 分发受影响 | 当前不走商店，不受影响；后续上架时用 `uses-feature` + 屏幕尺寸再过一遍 |
| 平板后台启动 Activity 被系统拦截 | 拦截页弹不出 | 已启用无障碍服务（系统白名单），沿用现有路径；真机验证 Android 12/13 |
| 两套 UI 逻辑漂移 | 规则表现不一致 | 平板上禁止新增业务逻辑；判分、阈值、题量全部走服务端同一接口 |
| 孩子直接卸载 App | 管控失效 | 一期靠家长端「离线告警」；设备管理器防卸载列入未决问题 |
| 国产 ROM 杀后台 | 守护失效 | 引导页提示 + 自检页可查看前台服务状态 |

## 11. 未决问题

1. **防卸载**：是否启用 `DeviceAdminReceiver`（卸载需先取消激活）？涉及「孩子能否自己卸掉」的根本问题，建议作为 085 单独设计。
2. **平板答题与电视额度是否互通**：当前额度按 `tv_device` 计，同一孩子多设备各自计数。是否需要「同一孩子跨设备合并每日上限」需产品确认。
3. **APK 分发**：目前靠数据线/文件中转；是否在家长端内置下载页（需要 8082 增加静态 APK 目录）。

## 附录 A：为什么不支持 iPad

| 能力 | iPad | 说明 |
| --- | --- | --- |
| 读取其他 App 使用时长 | ❌ | 无公开 API；`FamilyControls` 需苹果单独审批的特殊资质 |
| 强制弹出全屏答题接管 | ❌ | 系统不允许 App 抢占前台其他 App |
| 屏蔽指定 App | ⚠️ 仅特殊资质 | `ManagedSettings` 盾牌可屏蔽，但需要资质 + 家庭共享儿童账号，且做不出「答对才能看」 |
| 现有守护端移植 | ❌ | 无障碍/前台服务模型与安卓完全不同 |

结论：iPad 上只能使用苹果自带「屏幕使用时间 + 家人共享」做时长与应用限制，本项目不做 iPad 受管控端。家长端 iPad 版本（076）继续可用，用于查看与改规则。
