## 1. 目标

为每个对局的事件流增加单调递增版本号，SSE 通过 `id:` 与 `data.version` 暴露，便于客户端断线重连去重与判断事件新旧。

## 2. 实现

- 发布时生成版本：Redis `INCR battle:events:ver:<battleID>`；Redis 不可用时用进程内原子计数；
- 版本随事件在 broker 内分发（`chan int64` 或带版本结构）；
- SSE 输出：

```text
id: 12
event: update
data: {"version":12}

```

- 同一实例本地总线与 Redis 跨实例共享同一版本来源；
- 订阅时先发送当前 `version` 快照（可选，便于客户端建立基线）。

## 3. 语义

- 版本只增不减，允许因限流合并导致跳号；
- 客户端只处理 `version` 大于本地值的事件；
- 无事件时心跳仍可保持连接。

## 4. 风险

| 风险 | 对策 |
| --- | --- |
| Redis 不可用 | 本地原子计数兜底 |
| 并发发布顺序 | INCR 全局单调 |
| 旧客户端 | 忽略新增 id/version 字段 |
