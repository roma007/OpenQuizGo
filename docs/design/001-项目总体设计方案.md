## 0. 摘要

OpenQuizGo 是面向家庭的儿童电视观看管理产品：孩子在电视上答题，答对达到阈值后由**服务端**签发观看时长；家长通过手机端配置规则（时长、阈值、时段、学科权重、每日上限、趣味题开关），并查看成长报告。题库按「学科标签 + 学段 + 难度 + 题型」组织，配套治理、覆盖率看板、难度校准与推荐。

核心架构判断：**模块化单体（Go）+ PostgreSQL + Redis + 对象存储**，服务端为唯一裁决者；电视端是薄客户端；家长端独立 App。首发聚焦服务端基座（第一期），再上电视端与家长端。

| R13 | 家长端：规则设置、报告、推送、离线查看 | 关键操作需二次验证；规则变更实时下发 | P0 |
| R14 | 电视端：遥控器可达、大字体、语音答题、单题限时 | 全流程可仅用遥控器完成；焦点不丢失 | P0 |

## 4. 方案对比与选型

### 4.1 后端形态：BaaS 起步 vs 自建模块化单体

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. BaaS（Supabase/Firebase/LeanCloud） | 账号、数据库、推送开箱即用，起步快 | 大陆网络与合规不可控；规则引擎仍需自写服务；电视长连接/设备绑定能力弱；后期迁移成本高 | 否决 |
| B. 自建 Go 模块化单体 + PostgreSQL | 全链路可控；规则与判分天然服务端；一套语言；可私有化部署；迁移成本低 | 初期多 2–3 周基建 | **选用** |
| C. 微服务 | 隔离性好 | 团队规模不匹配，运维与一致性成本高 | 否决（后续按需拆分） |

**选型理由**：产品的核心资产是「规则 + 判分 + 题库」，这三者都必须服务端可控；大陆发行与儿童合规要求数据自主可控，BaaS 不可行。

### 4.2 客户端技术

| 端 | 方案 | 结论 |
| --- | --- | --- |
| Android TV | Kotlin + Jetpack Compose for TV + Media3/ExoPlayer | **选用**：DPAD 焦点、语音、播放器生态最成熟 |
| Android TV | Flutter | 否决：TV 焦点与播放器生态不成熟，低龄动画性能风险 |
| 家长端 | Flutter（Android/iOS 一套代码） | **选用**：表单与报表为主，跨端收益高 |
| 家长端 | 原生双端 | 备选：团队 Flutter 能力不足时启用 |

### 4.3 题库存储

| 方案 | 结论 |
| --- | --- |
| 按学科拆表/拆库 | 违反硬约束 1，否决 |
| 单表 + `tag_dict` 标签 + `schema_ver` | **选用** |

### 4.4 判分位置

| 方案 | 结论 |
| --- | --- |
| 客户端本地判分 | 可被改包/抓包绕过，违反硬约束 4，否决 |
| 服务端判分 + 一次性答题令牌 | **选用** |
| 离线判分 | 仅作为「离线租约」限时兜底，不产生新的解锁，否决作为主路径 |

### 4.5 部署形态

容器化部署（Docker + Kubernetes 或云托管容器），单地域多可用区；对象存储 + CDN 承载图片/音频；静态资源与 API 同域或独立网关。

### 5.2 模块职责

| 模块 | 职责 | 第一期 |
| --- | --- | --- |
| `identity` | 家长账号、家庭组、孩子档案、设备激活与绑定、家长 PIN/二次验证 | ✅ |
| `question` | 题目 CRUD、标签字典、导入导出、版本、审核流、上下架 | ✅（API + 导入，无 UI） |
| `quiz` | 组卷、答题会话、一次性令牌、判分、防重放 | ✅ |
| `rule` | 规则配置、快照、判定、权重与占比、时段与每日上限 | ✅ |
| `watch` | 观看授权（lease）、心跳、观看日志、断网租约 | ✅ |
| `report` | 答题/观看聚合、周/月报告 | ✅（基础聚合） |
| `admin` | 管理端 API、RBAC、审计 | ✅（API） |

| `billing` | 会员与订单 | 第五期（仅预留字段） |

### 5.3 关键流程

#### 5.3.1 设备激活

1. 电视启动，调用 `POST /v1/device/activate/code` 获得 6 位激活码 + 二维码，展示在电视上。
2. 家长端登录后扫描/输入激活码，选择孩子，调用 `POST /v1/family/devices/activate`。
3. 电视轮询 `POST /v1/device/token`，凭激活码换取长期设备令牌（写入 Android Keystore），同时上报设备指纹。
4. 服务端建立 `device_bind`（一台设备同一时刻仅一个孩子），旧绑定自动失效。

#### 5.3.2 解锁观看（主链路）

```
TV                        Server                         DB
 |-- GET /child/context -->|                              |
 |                         |-- 读取 rule + 今日观看/授权 --->|
 |<-- 可看状态/剩余时长 ----|                              |
 |-- POST /quiz/sessions ->|  时段校验 + 每日剩余校验        |
 |                         |-- 选题（学段/难度/权重/趣味上限）|
 |<-- 题目（无答案）+ 令牌 -|                              |
 |-- POST .../answers ---->|  一次性令牌校验 + 服务端判分    |
 |<-- 对错/解析/进度 -------|                              |
 |-- POST .../finish ----->|  达阈值 → 生成 watch_grant     |
 |<-- lease(分钟/到期) -----|                              |
 |-- 播放（校验 lease）                                      |
 |-- POST /watch/heartbeat>|  扣减已观看时长                 |
```

- 组卷默认题量 = `pass_threshold + 2`（上限 10），答对达阈值即提前结束。
- 学科权重决定**题目分布**；阈值默认按答对**题数**计（见 Q3）。
- 授权分钟数 = `min(unlock_minutes, 今日剩余额度)`；额度不足时不发或发剩余值（可配）。
- 心跳 30s 一次，服务端累计实际观看秒数；跨时段边界或额度耗尽时下发 `revoke`。

#### 5.3.3 断网降级

- 在线时预取「离线租约」：`GET /v1/offline/lease`，返回 EdDSA 签名令牌，含 `child_id / device_id / 允许内容 / 最大离线分钟(默认10) / 签发时间 / 绝对过期时间(24h)`。
- 离线播放由客户端可信播放模块计时，累计不超过租约分钟数；恢复网络后上报，服务端扣减当日额度并入库。
- **诚实说明**：离线状态无法 100% 防篡改（root/改包），通过 Keystore、完整性校验、付费内容 DRM 提高成本；离线不产生新的答题解锁。

#### 5.3.4 规则变更下发

- 家长修改规则 → 服务端版本号 +1 → 写 outbox → 推送（FCM/厂商通道）通知设备 → 电视下次请求或收到推送后拉取新规则。
- 任何请求都以服务端最新规则为准，客户端缓存仅用于展示，不作为判定依据。
- 修改需家长 PIN（或生物识别），并写 `audit_log`。

#### 5.3.5 题库发布与版本

- 状态机：`draft → review → trial → online → offline`，非法跃迁由服务端拒绝。
- 题目被抽中时记录 `question_version` 与答案快照到 `quiz_session_item`，保证会话期间改题不影响判分。
- 下线题目立即从在线池移除；已发出的会话继续有效（快照）。

## 6. 数据模型

### 6.1 设计原则

1. **单题库**：只有 `question` 一张题目主表，学科/类目/学段/题型全部是标签。
2. **标签字典化**：`tag_dict` 是唯一枚举来源，新增取值不改表结构。
3. **答案不出服务端**：任何面向客户端的响应都不得包含 `answer` / `answer_alias`（提交后判分响应除外）。
4. **一切判定留痕**：授权、规则变更、审核、上下架写审计日志。
5. **JSON 字段带 `schema_ver`**，迁移可回放。

### 6.2 核心表

#### `tag_dict`

| 字段 | 说明 |
| --- | --- |
| `tag_type` | subject / category / stage / grade / difficulty / type |
| `code` | 取值编码，如 `math` / `preschool` / `choice` |
| `name` | 展示名 |
| `sort` / `enabled` | 排序、启停 |

主键 `(tag_type, code)`。`subject` 字典：`math, chinese, english, science, logic, safety, fun`；`category`：`core, literacy, topic, fun`。

#### `question`

在 `idea.txt` 字段清单基础上补充：

| 字段 | 说明 |
| --- | --- |
| `subject_code` / `category_code` / `stage_code` / `type_code` | 外键到 `tag_dict`，服务层校验 |
| `grade_tag` | `g1~g9`，可空，仅学段内偏移 |
| `difficulty` | 1–5，可被校准任务调整 |
| `stem` / `stem_media` / `options` / `answer` / `answer_alias` / `explain` | 题干与答案，`options`、`answer` 为 JSON |
| `duration_limit` | 学科 ≤30s，趣味 10–20s（服务端校验） |
| `topic_id` | 专题题包 |
| `status` / `version` / `schema_ver` | 状态、版本、JSON schema 版本 |
| `created_by` / `reviewed_by` / 时间戳 | 责任链 |

**趣味题约束**：`category_code='fun'` 时，`answer_alias` 必填至少 1 条；不进学科矩阵统计；学段两档由 `stage` 派生（`preschool/low → 3–8`，`mid/high → 9+`），不新增字段、不破坏「学段必填」。

**索引**：`(status, stage_code, subject_code, difficulty)`、`(status, category_code)`、`(topic_id)`；题干全文检索后续再加 `pg_trgm`。

#### `topic_pack` / `topic_question`

题包元信息（类型、学科/学段范围、起止时间、是否付费、状态）+ 题目多对多关联。

#### 家庭与账号

| 表 | 关键字段 |
| --- | --- |
| `parent_account` | id、手机号（加密/脱敏）、密码哈希或验证码登录、状态 |
| `family` | id、owner_id、会员状态（预留）、创建时间 |
| `family_member` | family_id、account_id、角色（owner/member）、二次验证状态 |
| `child_profile` | id、family_id、昵称、生日（仅存年月）、`stage_code`、`grade_tag`、头像 |
| `device_bind` | id、device_id（设备指纹哈希）、child_id、端类型、状态、绑定时间、解绑时间 |

约束：`device_bind` 上 `(device_id) WHERE status='active'` 唯一；孩子删除时级联失效绑定。

#### `watch_rule`

沿用草案字段，补充：`version`、`timezone`（默认 Asia/Shanghai）、`effective_from`。`subject_weight` 形如 `{"math":0.5,"chinese":0.3,"english":0.2}`，服务端校验和为 1。

#### 答题与会话

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `quiz_session` | id、child_id、device_id、rule_version、state、question_count、pass_threshold、started_at、expires_at、finished_at | 一次解锁尝试 |
| `quiz_session_item` | id、session_id、question_id、question_version、position、answer_token_jti、issued_at、answered_at、answer_given、is_correct、duration_ms | 一题一次机会，令牌一次性 |
| `answer_log` | 草案字段 + session_id | 校准/报告数据源 |

状态：`active → passed / failed / expired / cancelled`。

#### 授权与观看

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `watch_grant` | id、child_id、device_id、session_id、minutes、valid_from、valid_until、jti、consumed_seconds、status | 服务端签发的观看许可 |
| `watch_log` | id、grant_id、child_id、device_id、content_id、start_at、end_at、watched_seconds | 心跳汇总与实际观看 |
| `offline_lease` | id、device_id、child_id、jti、max_minutes、issued_at、expires_at、reported_minutes、status | 离线降级对账 |

#### 报告与治理

| 表 | 说明 |
| --- | --- |
| `growth_report` | child_id、period(week/month)、period_start、subject_stats、fun_stats、watch_minutes、generated_at |
| `audit_log` | actor_type/id、action、target_type/id、before/after、ip、ua、created_at |
| `admin_user` / `admin_role` / `admin_permission` | RBAC，教研/审核/运营/管理员 |
| `media_asset` | 资源 id、类型、URL、时长、hash、审核状态 |

### 6.3 关键业务约束

- 学段只能取四档；`grade_tag` 仅在学段内做推荐偏移，不参与分组统计口径。
- 趣味题：`category_code='fun'`，不进入 `subject × stage × difficulty` 覆盖率考核；每次会话最多 `fun_ratio_cap`（默认 2）道。
- `watch_grant.minutes` 不得超过当日剩余额度；额度以 `watch_log` 实际秒数 + 未结算授权计。
- 一条 `quiz_session` 只能签发一次 `watch_grant`（幂等）。
- 所有时间以服务端 UTC 存储，展示层按家庭时区转换。

### 6.4 数据量与归档

- `answer_log`、`watch_log` 按月分区，保留 24 个月；`audit_log` 保留 36 个月。
- 报告表按孩子 + 周期唯一，生成任务幂等（upsert）。

### 6.5 演进

- `schema_ver` 与题目 `version` 分离：前者描述 JSON 结构，后者描述内容修订。
- 新增题型：加 `type` 字典 + 客户端渲染器 + 判分策略注册表，不改表。
- 新增学科：加 `subject` 字典，不改表。

## 7. 接口设计

### 7.1 通用约定

- Base path：`/v1`；JSON；UTF-8；时间为 RFC3339（UTC）。
- 鉴权：`Authorization: Bearer <token>`；电视端使用设备令牌，家长端使用短期 access token + 轮换 refresh token，管理端 JWT + RBAC。
- 幂等：写操作支持 `Idempotency-Key`；答题提交天然幂等（令牌一次性）。

## 8. 规则引擎设计

### 8.1 输入与输出

**输入**：`child_id`、`device_id`、`watch_rule`（含版本）、当前时间、当日观看秒数、当日已签发未消费额度、最近答题记录。

**输出**：是否允许发起答题、组卷参数、判定结果、授权分钟数。

### 8.2 判定顺序

1. 设备/孩子绑定有效。
2. 时段校验（支持跨零点配置）。
3. 每日额度校验（已看 + 已授权 + 本次预估 > `daily_limit` → 拒绝或降额）。
4. 生成规则快照（写入会话，保证会话期间规则稳定）。
5. 组卷 → 判分。
6. 达阈值 → 签发授权；否则拒绝并给出剩余机会。

### 8.3 组卷与阈值算法（草案）

```text
n = clamp(pass_threshold + 2, 3, 10)
quota = 按 subject_weight 分配 n（最大余数法，和为 n）
if fun_enabled: fun_count = min(fun_ratio_cap, max(0, n - 1))
for subject in quota:
    从 stage 池中按 difficulty 目标区间抽题
    排除该孩子最近 30 天做过的题（题量不足时放宽）
    优先补齐覆盖率低的难度档
乱序后落库 session_item，生成一次性 answer_token
通过条件：correct_count >= pass_threshold
授权分钟 = min(unlock_minutes, daily_limit - 今日已用 - 今日已授权)
```

- 难度目标默认 60%–80% 正确率，按孩子历史滚动调整（P1）。
- 趣味题不参与学科权重分配，单独占位。
- 题库断供兜底：降级到相邻难度/学段（记录告警），绝不返回空会话。

### 8.4 防绕过

| 手段 | 说明 |
| --- | --- |
| 答案不下发 | 组卷响应剥离 `answer` / `answer_alias` |
| 一次性令牌 | 每题一个 `jti`，提交即失效，重放返回 409 |
| 服务端计时 | `duration_ms = 服务端接收时间 - 签发时间`，<300ms 判异常 |
| 会话限额 | 单位时间内会话数、答题数限流 |
| 选项乱序 | 服务端生成展示顺序并落库，防止按位置背答案 |
| 设备绑定 | 设备令牌存 Keystore，解绑即失效 |
| 规则与判分 | 全在服务端，客户端仅展示 |

### 8.5 边界情况

- 跨零点时段：`20:00–07:00` 视为允许，按家庭时区计算。
- 会话中途规则变更：以会话快照为准，下次会话生效。
- 授权中途额度耗尽/进入禁看时段：心跳返回 `revoke`，客户端立即停播。
- 多设备并行：授权按设备签发，额度按孩子合并计算，Redis 分布式锁防超发。

## 9. 非功能设计

### 9.1 性能与容量

| 指标 | 目标 |
| --- | --- |
| 答题提交 p95 | ≤ 150ms |
| 其他读接口 p95 | ≤ 200ms |
| 组卷 p95 | ≤ 300ms |
| 可用性 | 99.9% |
| 峰值 | 1000 QPS / 1 万日活 |
| RPO / RTO | 15 分钟 / 1 小时 |

### 9.2 安全

- 全链路 HTTPS；令牌短期化 + 轮换；设备令牌可吊销。
- 密码/验证码限流；家长敏感操作二次验证。
- 数据库字段级加密（手机号、生日）；日志脱敏。
- 管理端独立域名/网段、RBAC、操作审计、导出水印。

### 9.3 合规（儿童产品）

- 遵循《个人信息保护法》《儿童个人信息网络保护规定》：监护人同意、最小必要、目的限定。
- 不采集精确位置、通讯录、广告标识；设备指纹哈希化。
- 生日仅存年月用于学段映射；提供数据导出与删除能力。
- 内容审核前置：儿童向内容禁止低俗、歧义、硬凑谐音；审核记录留存。
- 学科表述避免学科培训口径（用语审查清单）。

### 9.4 可观测性

- OpenTelemetry 链路追踪；Prometheus 指标（QPS、延迟、判分失败率、授权拒绝原因、断供格子数）。
- 结构化日志（slog），`request_id` 贯穿。
- 告警：5xx 比例、p95 超阈值、覆盖率断供、授权异常、会话异常高频。

### 9.5 运维

- 迁移工具：golang-migrate，仅向前迁移 + 可回滚脚本。
- 灰度：按家庭/设备维度开关；规则引擎支持 dry-run。
- 备份：PostgreSQL 每日全量 + WAL 归档；对象存储跨区复制。
