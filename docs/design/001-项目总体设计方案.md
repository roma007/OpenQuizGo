## 0. 摘要

OpenQuizGo 是面向家庭的儿童电视使用管理产品：孩子观看的是**第三方视频 App**，需先在电视守护端答题；答对累计**加权分**达到门槛后，由**服务端**签发一段可用时长；家长通过手机端配置规则（时长、加权门槛、学科权重、时段、每日上限、趣味题开关），并查看成长报告。题库按「学科标签 + 学段 + 难度 + 题型」组织，配套治理、覆盖率看板、难度校准与推荐。

核心架构判断：**模块化单体（Go）+ PostgreSQL + Redis + 对象存储**，服务端为唯一裁决者；电视端是**守护端**（识别前台应用、遮罩拦截、计时上报），不是内容播放器；家长端独立 App。答题弹出时守护端尝试自动暂停当前播放的视频、答完恢复，并**不计入使用时长**；该能力依赖第三方播放器的媒体会话，属「尽力而为」，需按 App 实测。因管控对象是第三方 App，**设备级管控能力（无障碍 / 悬浮窗 / Device Owner）是本项目最大的技术风险**，必须先做第 0 期可行性验证。

## 4. 方案对比与选型

### 4.1 后端形态：BaaS 起步 vs 自建模块化单体

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. BaaS（Supabase/Firebase/LeanCloud） | 账号、数据库、推送开箱即用，起步快 | 大陆网络与合规不可控；规则引擎仍需自写服务；电视长连接/设备绑定能力弱；后期迁移成本高 | 否决 |
| B. 自建 Go 模块化单体 + PostgreSQL | 全链路可控；规则与判分天然服务端；一套语言；可私有化部署；迁移成本低 | 初期多 2–3 周基建 | **选用** |
| C. 微服务 | 隔离性好 | 团队规模不匹配，运维与一致性成本高 | 否决（后续按需拆分） |

**选型理由**：产品的核心资产是「规则 + 判分 + 题库」，这三者都必须服务端可控；大陆发行与儿童合规要求数据自主可控，BaaS 不可行。

### 4.2 客户端技术

| 端 | 方案 | 结论 |
| --- | --- | --- |
| Android TV | Kotlin + Jetpack Compose for TV + AccessibilityService/悬浮窗/UsageStats | **选用**：DPAD 焦点与系统管控能力最成熟 |
| Android TV | Flutter | 否决：TV 焦点与系统管控能力不成熟，低龄动画性能风险 |
| 家长端 | Flutter（Android/iOS 一套代码） | **选用**：表单与报表为主，跨端收益高 |
| 家长端 | 原生双端 | 备选：团队 Flutter 能力不足时启用 |

### 4.3 题库存储

| 方案 | 结论 |
| --- | --- |
| 按学科拆表/拆库 | 违反硬约束 1，否决 |
| 单表 + `tag_dict` 标签 + `schema_ver` | **选用** |

### 4.4 判分位置

| 方案 | 结论 |
| --- | --- |
| 客户端本地判分 | 可被改包/抓包绕过，违反硬约束 4，否决 |
| 服务端判分 + 一次性答题令牌 | **选用** |
| 离线判分 | 仅作为「离线租约」限时兜底，不产生新的解锁，否决作为主路径 |

### 4.5 部署形态

容器化部署（Docker + Kubernetes 或云托管容器），单地域多可用区；对象存储 + CDN 承载图片/音频；静态资源与 API 同域或独立网关。

### 4.6 电视端管控方案（第三方 App 场景）

管控目标是「限制第三方视频 App 的可用时段与总时长」，不是控制播放器。可选手段：

| 方案 | 能力 | 限制 | 结论 |
| --- | --- | --- | --- |
| A. Device Owner / DPC | 挂起/恢复应用、锁定任务、禁用状态栏、防卸载 | 需恢复出厂 + 激活配置，或厂商预装/ADB provisioning | **增强模式**（生产首选，需商务/实施配合） |
| B. AccessibilityService + 悬浮窗 + UsageStats | 识别前台包名、全屏遮罩、回桌面、按前台时长计时 | 用户可在设置中关闭无障碍/悬浮窗；部分系统界面不可覆盖；应用商店政策需合规声明 | **标准模式**（首发，必须 PoC 验证） |
| C. 自定义 Launcher | 收敛应用入口，展示答题与倒计时 | 系统设置、遥控器快捷键、其他 Launcher 可绕过 | 辅助手段，与 B 组合 |
| D. 本地 VPN 断网 | 无授权时阻断指定应用流量 | 体验粗暴、隐私敏感、无法表达「时长」语义 | 不采用 |
| E. 厂商预装/系统级集成 | 最彻底，权限与稳定性最好 | 依赖电视厂商合作 | 合作目标 |

**决策**：采用「双模式」——

- **标准模式（首发）**：守护端申请「使用情况访问 + 悬浮窗 + 无障碍」三项权限，并按需申请「通知使用权」用于媒体会话控制；前台应用切换时判定是否有有效授权；无授权则覆盖全屏遮罩并提供「去答题 / 回桌面」。
- **增强模式（后续/合作）**：Device Owner 下用 `setPackagesSuspended` 精确挂起应用，防卸载、防关闭，可靠性最高。
- 两种模式共用同一套服务端授权协议，客户端按能力上报 `guard_mode`。

**必须在第 0 期 PoC 验证**（详见实施计划 T0）：

1. 在 2–3 台目标机型上，遮罩能否覆盖主流视频 App 的全屏播放界面。
2. 前台应用识别延迟、无障碍服务在重启/待机/系统升级后的存活情况。
3. 用户关闭权限、卸载守护端的检测与恢复路径。
4. Device Owner 在目标机型上的可实施性（ADB/二维码 provisioning）。

### 4.7 答题时暂停/恢复第三方播放

目标：题目弹出时暂停当前视频，答题结束恢复；答题期间**不累计使用时长**。

| 手段 | 原理 | 覆盖 | 限制 |
| --- | --- | --- | --- |
| A. MediaSession 控制 | 通知使用权获取 `MediaController`，调用 `transportControls.pause()/play()` | 最精准，可读播放状态 | App 未暴露 MediaSession 则无效 |
| B. 音频焦点 | `requestAudioFocus(GAIN_TRANSIENT)`，播放器收到失焦后暂停 | 最广 | 部分播放器只降音不暂停，恢复行为不一 |
| C. 媒体按键 | `dispatchMediaKeyEvent(KEYCODE_MEDIA_PAUSE/PLAY)` | 较广 | 部分 App 忽略或弹出媒体控制层 |
| D. 全屏遮罩抢焦点 | 遮罩窗口获得焦点，触发播放器 `onWindowFocusChanged` | 部分 | 依赖 App 实现 |
| E. 无障碍点按 | 查找播放/暂停按钮节点并点击 | 兜底 | 脆弱，需逐 App 适配 |

**决策**：按 **A → B → C → D → E** 顺序组合尝试；进入答题前记录 `was_playing`、目标包名与媒体会话 id；恢复时**仅对原本在播、且仍在前台的 App** 执行；全部失败时遮罩提示「请手动暂停」。

**明确边界**：这不是 100% 可控能力。第三方 App 可能忽略全部标准信号、恢复后回到首页/广告、直播无法续播到原位置。产品文案与验收口径必须按「成功率」而非「必然」表述，具体阈值由第 0 期 PoC 实测后确定（暂定暂停 ≥90%、恢复 ≥85%）。

### 4.8 管控范围：媒体感知而非应用清单

评审意见：「允许应用清单」不是必须项，做题期间任何视频都应暂停/恢复。据此默认改为**媒体感知**，`custom` 清单保留为识别失败时的可选补录（最终以 Q3 确认）。

| 模式 | 判定 | 适用 |
| --- | --- | --- |
| `media`（默认） | `MediaSession` 活跃或系统音频流正在播放 → 视为「观看中」，受时段/额度约束 | 覆盖主流视频 App，不误伤设置/相册等 |
| `custom`（可选） | 家长勾选的应用清单，未勾选不限制 | 需要精确控制的家庭 |
| `all_apps`（预留） | 除系统白名单外所有前台应用 | 更严格的屏幕时间 |

默认 `media`。若某 App 播放时不暴露 MediaSession，则用「前台应用 + 音频输出」兜底识别；仍识别不到的 App 由家长通过 `custom` 清单补录。该策略需在 PoC 中验证识别率。

### 5.2 模块职责

| 模块 | 职责 | 第一期 |
| --- | --- | --- |
| `identity` | 家长账号、家庭组、孩子档案、设备激活与绑定、家长 PIN/二次验证 | ✅ |
| `question` | 题目 CRUD、标签字典、导入导出、版本、审核流、上下架 | ✅（API + 导入，无 UI） |
| `quiz` | 组卷、答题会话、一次性令牌、判分、防重放 | ✅ |
| `rule` | 规则配置、快照、判定、权重与占比、时段与每日上限 | ✅ |
| `watch` | 使用授权（lease）、心跳、应用使用日志、断网租约、异常上报 | ✅ |
| `report` | 答题/观看聚合、周/月报告 | ✅（基础聚合） |
| `admin` | 管理端 API、RBAC、审计 | ✅（API） |
| `notify` | 推送（规则变更、报告、绑定确认） | 第二期 |
| `billing` | 会员与订单 | 第五期（仅预留字段） |

### 5.3 关键流程

#### 5.3.1 设备激活

1. 电视启动，调用 `POST /v1/device/activate/code` 获得 6 位激活码 + 二维码，展示在电视上。
2. 家长端登录后扫描/输入激活码，选择孩子，调用 `POST /v1/family/devices/activate`。
3. 电视轮询 `POST /v1/device/token`，凭激活码换取长期设备令牌（写入 Android Keystore），同时上报设备指纹。
4. 服务端建立 `device_bind`（一台设备同一时刻仅一个孩子），旧绑定自动失效。
5. 守护端引导开启「使用情况访问 / 悬浮窗 / 无障碍」（标准模式），并通过 `PUT /device/capability` 上报权限状态；增强模式则完成 Device Owner 配置。

#### 5.3.2 解锁观看（主链路）

```
TV                        Server                         DB
 |-- GET /child/context -->|                              |
 |                         |-- 读取 rule + 今日观看/授权 --->|
 |<-- 可看状态/剩余时长 ----|                              |
 |-- 暂停当前播放（本地） ---|                              |
 |-- POST /quiz/sessions ->|  时段校验 + 每日剩余校验        |
 |                         |-- 选题（学段/难度/权重/趣味上限）|
 |<-- 题目（无答案）+ 令牌 -|                              |
 |-- POST .../answers ---->|  一次性令牌校验 + 服务端判分    |
 |<-- 对错/解析/进度 -------|                              |
 |-- POST .../finish ----->|  达阈值 → 生成 watch_grant     |
 |<-- lease(分钟/到期) -----|                              |
 |-- 恢复原播放（若原本在播）-|                              |
 |-- 放行前台 App（校验 lease；无授权则遮罩）                 |
 |-- POST /watch/heartbeat>|  扣减时长 + 上报前台包名        |
```

- 组卷题量按加权门槛反推：`n = clamp(ceil(pass_threshold / 加权均值) + 2, 3, 12)`；加权分达门槛即提前结束。
- **加权计分**：每答对一题得该学科 `subject_weight` 分，`pass_threshold` 是加权总分门槛（示例：数学 2 分、常识 1 分、趣味 0.5 分，门槛 3 分）。
- 题目分布仍按权重做倾向性分配（重数学则数学题更多），但**解锁与否只看加权总分**。
- 授权分钟数 = `min(unlock_minutes, 今日剩余额度)`；额度不足时不发或发剩余值（可配）。
- 进入答题前：按 4.7 的顺序暂停当前播放并记录 `was_playing`、包名、媒体会话；进入与恢复时各发一次即时心跳（带 `paused` 标记），避免按 30s 周期误计时。
- 答题结束：仅当原媒体会话仍存在、App 仍在前台且原本在播时恢复；否则保持暂停，避免误恢复。
- 心跳 30s 一次，携带前台包名与本地计时；服务端累计实际使用秒数，跨时段边界、额度耗尽或检测到异常时下发 `revoke`。
- 守护端切换前台应用时本地先判（租约 + 允许应用清单），服务端心跳做二次校验与对账。

#### 5.3.3 断网降级

- 在线时预取「离线租约」：`GET /v1/offline/lease`，返回 EdDSA 签名令牌，含 `child_id / device_id / 允许应用清单 / 最大离线分钟(默认10) / 签发时间 / 绝对过期时间(24h)`。
- 离线期间由守护端本地计时并拦截，累计不超过租约分钟数；恢复网络后上报，服务端扣减当日额度并入库。
- **诚实说明**：离线状态无法 100% 防篡改（root/改包/杀进程），通过 Keystore、设备完整性校验、权限存活检测提高成本；离线不产生新的答题解锁。
- 离线期间守护端被强制停止时无法拦截，属于已知边界，需通过家长端告警与权限守护缓解。

#### 5.3.4 规则变更下发

- 家长修改规则 → 服务端版本号 +1 → 写 outbox → 推送（FCM/厂商通道）通知设备 → 电视下次请求或收到推送后拉取新规则。
- 任何请求都以服务端最新规则为准，客户端缓存仅用于展示，不作为判定依据。
- 修改需家长 PIN（或生物识别），并写 `audit_log`。

#### 5.3.5 题库发布与版本

- 状态机：`draft → review → trial → online → offline`，非法跃迁由服务端拒绝。
- 题目被抽中时记录 `question_version` 与答案快照到 `quiz_session_item`，保证会话期间改题不影响判分。
- 下线题目立即从在线池移除；已发出的会话继续有效（快照）。

## 6. 数据模型

### 6.1 设计原则

1. **单题库**：只有 `question` 一张题目主表，学科/类目/学段/题型全部是标签。
2. **标签字典化**：`tag_dict` 是唯一枚举来源，新增取值不改表结构。
3. **答案不出服务端**：任何面向客户端的响应都不得包含 `answer` / `answer_alias`（提交后判分响应除外）。
4. **一切判定留痕**：授权、规则变更、审核、上下架写审计日志。
5. **JSON 字段带 `schema_ver`**，迁移可回放。

### 6.2 核心表

#### `tag_dict`

| 字段 | 说明 |
| --- | --- |
| `tag_type` | subject / category / stage / grade / difficulty / type |
| `code` | 取值编码，如 `math` / `preschool` / `choice` |
| `name` | 展示名 |
| `sort` / `enabled` | 排序、启停 |

主键 `(tag_type, code)`。`subject` 字典：`math, chinese, english, science, logic, safety, fun`；`category`：`core, literacy, topic, fun`。

#### `question`

在 `idea.txt` 字段清单基础上补充：

| 字段 | 说明 |
| --- | --- |
| `subject_code` / `category_code` / `stage_code` / `type_code` | 外键到 `tag_dict`，服务层校验 |
| `grade_tag` | `g1~g9`，可空，仅学段内偏移 |
| `difficulty` | 1–5，可被校准任务调整 |
| `stem` / `stem_media` / `options` / `answer` / `answer_alias` / `explain` | 题干与答案，`options`、`answer` 为 JSON |
| `duration_limit` | 学科 ≤30s，趣味 10–20s（服务端校验） |
| `topic_id` | 专题题包 |
| `status` / `version` / `schema_ver` | 状态、版本、JSON schema 版本 |
| `created_by` / `reviewed_by` / 时间戳 | 责任链 |

**趣味题约束**：`category_code='fun'` 时，`answer_alias` 必填至少 1 条；不进学科矩阵统计；学段两档由 `stage` 派生（`preschool/low → 3–8`，`mid/high → 9+`），不新增字段、不破坏「学段必填」。

**索引**：`(status, stage_code, subject_code, difficulty)`、`(status, category_code)`、`(topic_id)`；题干全文检索后续再加 `pg_trgm`。

#### `topic_pack` / `topic_question`

题包元信息（类型、学科/学段范围、起止时间、是否付费、状态）+ 题目多对多关联。

#### 家庭与账号

| 表 | 关键字段 |
| --- | --- |
| `parent_account` | id、手机号（加密/脱敏）、密码哈希或验证码登录、状态 |
| `family` | id、owner_id、会员状态（预留）、创建时间 |
| `family_member` | family_id、account_id、角色（owner/member）、二次验证状态 |
| `child_profile` | id、family_id、昵称、生日（仅存年月）、`stage_code`、`grade_tag`、头像 |
| `device_bind` | id、device_id（设备指纹哈希）、child_id、端类型、状态、绑定时间、解绑时间 |

约束：`device_bind` 上 `(device_id) WHERE status='active'` 唯一；孩子删除时级联失效绑定。

#### `watch_rule`

沿用草案字段，补充：`version`、`timezone`（默认 Asia/Shanghai）、`effective_from`、`weight_preset`（balanced/math/literacy/custom）、`scope_mode`（media/custom/all_apps，默认 media）、`allowed_apps`（`custom` 模式下的应用白名单）。`subject_weight` 是**每科答对一题的折算分**，如 `{"math":2,"chinese":1.5,"science":1,"fun":0.5}`；`pass_threshold` 是**加权总分门槛**（如 3），不再表示题数。服务端校验：权重非全零、趣味权重低于学科权重、门槛在当前题量与题池下可达。

#### 答题与会话

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `quiz_session` | id、child_id、device_id、rule_version、state、question_count、pass_threshold、paused_app、was_playing、paused_at、resumed_at、started_at、expires_at、finished_at | 一次解锁尝试，含暂停/恢复现场 |
| `quiz_session_item` | id、session_id、question_id、question_version、position、answer_token_jti、issued_at、answered_at、answer_given、is_correct、duration_ms | 一题一次机会，令牌一次性 |
| `answer_log` | 草案字段 + session_id | 校准/报告数据源 |

状态：`active → passed / failed / expired / cancelled`。

#### 授权与观看

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `watch_grant` | id、child_id、device_id、session_id、minutes、valid_from、valid_until、jti、consumed_seconds、status | 服务端签发的观看许可 |
| `watch_log` | id、grant_id、child_id、device_id、target_type(app/content)、target_id(包名)、start_at、end_at、watched_seconds、paused_seconds | 心跳汇总与前台应用使用（答题暂停时段单列，不计额度） |
| `offline_lease` | id、device_id、child_id、jti、max_minutes、allowed_apps、issued_at、expires_at、reported_minutes、status | 离线降级对账 |
| `device_capability` | device_id、guard_mode(standard/device_owner)、权限状态(json)、系统版本、最后上报 | 能力与权限存活检测 |
| `tamper_event` | id、device_id、child_id、type(权限关闭/卸载/改包/时钟异常)、detail、reported_at | 防绕过告警 |

#### 报告与治理

| 表 | 说明 |
| --- | --- |
| `growth_report` | child_id、period(week/month)、period_start、subject_stats、fun_stats、watch_minutes、generated_at |
| `audit_log` | actor_type/id、action、target_type/id、before/after、ip、ua、created_at |
| `admin_user` / `admin_role` / `admin_permission` | RBAC，教研/审核/运营/管理员 |
| `media_asset` | 资源 id、类型、URL、时长、hash、审核状态 |

### 6.3 关键业务约束

- 学段只能取四档；`grade_tag` 仅在学段内做推荐偏移，不参与分组统计口径。
- 趣味题：`category_code='fun'`，不进入 `subject × stage × difficulty` 覆盖率考核；每次会话最多 `fun_ratio_cap`（默认 2）道。
- 权重规则：`subject_weight` 全为 0 拒绝；趣味权重必须低于最低学科权重；`pass_threshold` 必须能被「题量 × 可达权重组合」满足，保存时校验，避免家长配出永远解锁不了的规则。
- `scope_mode=media` 时以媒体播放状态判定管控对象，`allowed_apps` 不生效；`custom` 时仅放行清单内应用；`all_apps` 时除系统白名单外均受限。
- 答题期间的暂停时长写入 `watch_log.paused_seconds`，不计入 `daily_limit`，也不扣减授权。
- `watch_grant.minutes` 不得超过当日剩余额度；额度以 `watch_log` 实际秒数 + 未结算授权计。
- 一条 `quiz_session` 只能签发一次 `watch_grant`（幂等）。
- 所有时间以服务端 UTC 存储，展示层按家庭时区转换。

### 6.4 数据量与归档

- `answer_log`、`watch_log` 首期普通表 + 索引；数据量达到阈值后按 `answered_at` / `start_at` 月分区（预留迁移），保留 24 个月；`audit_log` 保留 36 个月。
- 报告表按孩子 + 周期唯一，生成任务幂等（upsert）。

### 6.5 演进

- `schema_ver` 与题目 `version` 分离：前者描述 JSON 结构，后者描述内容修订。
- 新增题型：加 `type` 字典 + 客户端渲染器 + 判分策略注册表，不改表。
- 新增学科：加 `subject` 字典，不改表。

## 8. 规则引擎设计

### 8.1 输入与输出

**输入**：`child_id`、`device_id`、`watch_rule`（含版本）、当前时间、当日观看秒数、当日已签发未消费额度、最近答题记录。

**输出**：是否允许发起答题、组卷参数、判定结果、授权分钟数。

### 8.2 判定顺序

1. 设备/孩子绑定有效。
2. 时段校验（支持跨零点配置）。
3. 每日额度校验（已看 + 已授权 + 本次预估 > `daily_limit` → 拒绝或降额）。
4. 生成规则快照（写入会话，保证会话期间规则稳定）。
5. 组卷 → 判分。
6. 达阈值 → 签发授权；否则拒绝并给出剩余机会。

### 8.3 加权计分、组卷与可达性（核心算法）

#### 8.3.1 规则语义

家长配置三项，职责分离：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `pass_threshold` | 解锁所需的**加权总分门槛** | 3 分 |
| `subject_weight` | **每科答对一题的折算分** | 数学 2、语文 1.5、科学 1、趣味 0.5 |
| `fun_ratio_cap` | 单次会话趣味题**数量上限** | 2 道 |

示例（门槛 3 分）：2 道数学（4 分）或 3 道科学（3 分）可解锁；1 道数学 + 1 道趣味（2.5 分）不够；趣味题权重低且有数量上限，无法靠刷趣味题凑分。

#### 8.3.2 组卷

```text
enabled = 规则启用的学科（权重 > 0）
n_min = max(3, ceil(pass_threshold / max(subject_weight)))   # 理论上最少题数
n = clamp(n_min + 2, 3, 12)
if fun_enabled:
    fun_n = min(fun_ratio_cap, max(1, n - 1))
else:
    fun_n = 0
n_subject = n - fun_n
quota[subject] = 按 subject_weight 对 n_subject 做最大余数分配
quota[fun] = fun_n
for subject in quota:
    从 stage 池中按 difficulty 目标区间抽题
    排除该孩子最近 30 天做过的题（题量不足时放宽）
    优先补齐覆盖率低的难度档
乱序后落库 session_item，生成一次性 answer_token
```

#### 8.3.3 判定

```text
score = Σ (答对 ? subject_weight[subject] : 0)
通过 = score >= pass_threshold
授权分钟 = min(unlock_minutes, daily_limit - 今日已用 - 今日已授权)
```

#### 8.3.4 可达性校验（保存规则时）

1. 权重非全零；趣味权重必须小于最低学科权重（无趣味权重时忽略）。
2. 按题量 n 计算最大可得加权分 `maxScore = Σ quota[i] × weight[i]`，要求 `maxScore ≥ pass_threshold`。
3. 若 `pass_threshold` 只能靠全对达成，返回「难度警告」而非拒绝。
4. 题库断供时按相邻难度/学段降级并告警，绝不返回空会话；若降级后仍不可达，拒绝本次解锁并提示家长。

#### 8.3.5 家长端预设档位

| 预设 | 权重（数学/语文/英语/科学/逻辑/安全/趣味） | 默认门槛 |
| --- | --- | --- |
| 均衡 | 1.5 / 1.5 / 1.5 / 1 / 1 / 1 / 0.5 | 3 |
| 重数学 | 2 / 1.2 / 1.2 / 1 / 1 / 1 / 0.5 | 3 |
| 重素养 | 1.2 / 1.2 / 1 / 2 / 2 / 2 / 0.5 | 3 |

家长端默认只选预设，进阶模式才逐科调整；保存时执行 8.3.4 校验，避免「永远解锁不了」。

### 8.4 防绕过

| 手段 | 说明 |
| --- | --- |
| 答案不下发 | 组卷响应剥离 `answer` / `answer_alias` |
| 一次性令牌 | 每题一个 `jti`，提交即失效，重放返回 409 |
| 服务端计时 | `duration_ms = 服务端接收时间 - 签发时间`，<300ms 判异常 |
| 会话限额 | 单位时间内会话数、答题数限流 |
| 选项乱序 | 服务端生成展示顺序并落库，防止按位置背答案 |
| 设备绑定 | 设备令牌存 Keystore，解绑即失效 |
| 守护权限存活 | 检测无障碍/悬浮窗/使用统计是否被关闭，立即上报家长端 |
| 应用白名单 | 非白名单应用一律遮罩，防止换 App 绕过 |
| 防卸载 | Device Owner 模式禁止卸载；标准模式检测卸载并告警 |
| 时钟校验 | 客户端时间与服务端偏差过大时标记异常并限制授权 |
| 规则与判分 | 全在服务端，客户端仅展示 |

### 8.5 边界情况

- 跨零点时段：`20:00–07:00` 视为允许，按家庭时区计算。
- 会话中途规则变更：以会话快照为准，下次会话生效。
- 授权中途额度耗尽/进入禁看时段：心跳返回 `revoke`，守护端立即遮罩。
- 多设备并行：授权按设备签发，额度按孩子合并计算，Redis 分布式锁防超发。
- 守护权限被关闭/进程被杀：本地无法拦截，上报 `tamper_event` 并推送家长；额度仍按最后一次上报结算。
- HDMI 外接、投屏、手机热点等其他观看路径不在管控范围，需在家长协议与产品说明中明示。

## 9. 非功能设计

### 9.1 性能与容量

| 指标 | 目标 |
| --- | --- |
| 答题暂停响应 | 本地 ≤ 500ms（从弹题到画面暂停） |
| 答题提交 p95 | ≤ 150ms |
| 其他读接口 p95 | ≤ 200ms |
| 组卷 p95 | ≤ 300ms |
| 可用性 | 99.9% |
| 峰值 | 1000 QPS / 1 万日活 |
| RPO / RTO | 15 分钟 / 1 小时 |

### 9.2 安全

- 全链路 HTTPS；令牌短期化 + 轮换；设备令牌可吊销。
- 密码/验证码限流；家长敏感操作二次验证。
- 数据库字段级加密（手机号、生日）；日志脱敏。
- 管理端独立域名/网段、RBAC、操作审计、导出水印。

### 9.3 合规（儿童产品）

- 遵循《个人信息保护法》《儿童个人信息网络保护规定》：监护人同意、最小必要、目的限定。
- 不采集精确位置、通讯录、广告标识；设备指纹哈希化。
- 生日仅存年月用于学段映射；提供数据导出与删除能力。
- 使用情况访问、无障碍、悬浮窗、通知使用权属于敏感权限：首次开启需逐项说明用途，仅采集前台包名、媒体会话状态与使用时长，不上传画面与内容；提供关闭入口与隐私政策。
- 内容审核前置：儿童向内容禁止低俗、歧义、硬凑谐音；审核记录留存。
- 学科表述避免学科培训口径（用语审查清单）。

### 9.4 可观测性

- OpenTelemetry 链路追踪；Prometheus 指标（QPS、延迟、判分失败率、授权拒绝原因、断供格子数）。
- 结构化日志（slog），`request_id` 贯穿。
- 告警：5xx 比例、p95 超阈值、覆盖率断供、授权异常、会话异常高频。

### 9.5 运维

- 迁移工具：golang-migrate，仅向前迁移 + 可回滚脚本。
- 灰度：按家庭/设备维度开关；规则引擎支持 dry-run。
- 备份：PostgreSQL 每日全量 + WAL 归档；对象存储跨区复制。
