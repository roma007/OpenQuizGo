## 1. 背景与目标

### 现状与问题

080 把电视端从本地单机恢复成了服务端模式，但接入模型沿用的是 073 时代的设想：

1. **靠激活码绑定**：电视显示 6 位码，家长在手机上确认。用户认为这一步多余——所有客户端都应该注册登录。
2. **配置挂在"孩子"上**（`watch_rule.child_id unique`）：一台电视对应一个孩子，客厅电视和卧室电视只能共用一套规则。用户要求按**每台电视**分别配置。
3. **电视首页是运维大屏**：前台应用、媒体播放、守护状态、剩余授权、诊断入口全堆在一页。用户明确不需要配置页，配置全部收到家长端。
4. **自检常驻**：首页一行"无障碍 ✓/✗"，用户要的是**开机自检**，通过就不显示，不通过才弹对应引导。
5. **上限是软限制**：额度用完只是"不再弹题"，界面还能退出去继续看。用户要**硬停**。

### 本次目标（可验证）

- G1 电视端用**手机号 + 短信验证码**登录，登录后长期免登录（设备令牌 365 天）。
- G2 电视端**没有配置页**；点开 App 只看到只读状态页（今日已看 / 剩余 / 下次答题倒计时）。
- G3 配置**按电视**下发：做题开关、题目范围、强制答题间隔、每日上限、上限开关。
- G4 新电视默认：做题开关**开**、**做所有题**、**每 15 分钟**强制答题、**每日 60 分钟**上限、上限开关**开**。
- G5 每日上限到点**硬停**：满屏不可退出，切走后 1 秒内被重新拉起。
- G6 **每次开机自检**：全过静默；有失败项就逐项弹引导。
- G7 家长端新增"电视列表 + 每台电视设置"，替代现有的"绑定电视"流程。

### 非目标（明确不做什么）

- **微信扫码登录本期不实装**：需要微信开放平台「网站应用」资质 + 已备案域名回调，备案未通过。仅预留入口与接口位（`login_method` 字段），资质齐了再接。
- 不做 Device Owner / 设备管理员级管控（那才能做到"物理上退不出去"）。
- 不删除孩子档案：孩子仍用于题目难度与成长报告，但**不再承载观看规则**。
- 不做家庭内多家长权限细分（沿用现有 owner 模型）。
- 不改答题判分、题库、会员、对战任何逻辑。

## 2. 需求与验收标准

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| R1 | 电视端登录 | 输入手机号 → 收验证码 → 登录成功，返回设备令牌；重启 App 不再要求登录 | P0 |
| R2 | 设备令牌权限隔离 | 设备令牌调 `/v1/family/**` 返回 403；只能访问 `/v1/tv/**` 与 `/v1/device/**` | P0 |
| R3 | 电视端无配置页 | 自检通过且非答题/拦截时，点开 App 只有只读状态页，无任何开关 | P0 |
| R4 | 按电视配置 | 家长端可对同一家庭的两台电视设置不同间隔与上限，各自生效 | P0 |
| R5 | 默认值 | 新电视登录后：`quiz_enabled=true`、`limit_enabled=true`、`unlock_minutes=15`、`daily_limit=60`、`subjects=[]`（全部） | P0 |
| R6 | 两个开关独立 | 关做题开关 → 不再弹题，但到 60 分钟仍硬停；关上限开关 → 不硬停，但仍弹题 | P0 |
| R7 | 硬停 | 上限到点 → 全屏页、返回键无效、按 Home 后 1 秒内被重新拉起；输入家长 PIN 可解除 | P0 |
| R8 | 开机自检 | 每次开机逐项检查；全过不显示任何界面；有失败项只弹失败项的引导 | P0 |
| R9 | 配置实时生效 | 家长改配置后，电视 60 秒内生效（复用现有 context 轮询） | P1 |
| R10 | 旧设备兼容 | 已绑定的旧版电视继续可用，不被强制踢出 | P1 |
| R11 | 未指定孩子的电视 | 组卷从全库随机取题，**不按年级/难度过滤**（只受题目范围约束） | P0 |
| R12 | 指定孩子 | 家长输入昵称（有默认值）+ N 年级；年级每年 9 月 1 日自动 +1，封顶 9 年级 | P0 |
| R13 | 硬停放行时长可配 | 家长端可设 1–120 分钟，默认 10 分钟；到期自动恢复硬停 | P0 |

## 3. 方案对比与选型

### 3.1 电视接入方式

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A 激活码绑定（现状） | 遥控器零输入 | 用户明确否决；多一步手机确认；概念上"设备"不是"客户端" | 淘汰 |
| B 手机号 + 验证码登录 | 与家长端同一套账号体系；遥控器只输一次；令牌 365 天 | 首次输入手机号较慢（11 位数字） | **选定** |
| C 微信扫码 | 零输入 | 需开放平台资质 + 备案域名；当前做不到 | 预留 |
| D 电视独立账号 | 隔离彻底 | 家长要维护两套账密，无收益 | 淘汰 |

选型理由：B 与"所有客户端都要注册登录"的目标一致，且能复用现有 `identity` 的短信与令牌设施，改动最小。C 作为 B 的补充通道，等资质齐了加一个登录 tab，不改数据模型。

### 3.2 配置归属

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A 挂在孩子（现状 `watch_rule`） | 无迁移 | 多台电视无法区分 | 淘汰 |
| B 挂在电视（新增 `tv_config`） | 符合"每台电视分别配置" | 需要新表 + 新接口 | **选定** |
| C 家庭级统一 | 简单 | 多电视场景失效 | 淘汰 |

选型理由：用户明确要求按电视配置。`watch_rule` 保留为**孩子级默认模板**：新电视登录时从中复制一次，之后独立演进（避免同一孩子两台电视互相改配置）。迁移期两套并存，旧设备继续读 `watch_rule`。

### 3.3 自检形态

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A 首页常驻状态（现状） | 随时可见 | 日常无用，泄露额度等内部信息 | 淘汰 |
| B 开机自检 + 按项引导 | 只在有问题时打扰 | 需要开机时机与去重 | **选定** |

## 4. 总体架构

### 模块职责

| 模块 | 改动 |
| --- | --- |
| `internal/identity` | 新增电视登录 `POST /v1/tv/login`；设备令牌 scope 校验；`tv_device` 落库 |
| `internal/rule` | 新增按设备读取配置；`/v1/tv/context` 返回设备配置与硬停判定 |
| `internal/quiz` | 组卷改用设备配置（题目范围、间隔、阈值） |
| `internal/watch` | 授权签发改用设备配置；硬停事件上报 |
| `parent`（Flutter） | 新增电视列表 + 每台设置页；下线"绑定电视" |
| `tv`（Android） | 登录页、自检引导页、只读状态页、硬停页；删除激活码与首页大屏 |

### 关键流程

**电视登录**

```
TV: 输入手机号 → POST /v1/auth/sms/code {phone, client:"tv"}
TV: 输入验证码 → POST /v1/tv/login {phone, code, device_id, device_name}
服务端: 校验验证码 → 查/建 tv_device（挂到该手机号所属家庭）
      → 生成设备令牌（scope=device，365 天）
      → 若首次登录，按 watch_rule 复制一份 tv_config（无则用默认值）
TV: 保存令牌 → 进入守护态（不显示任何页面）
```

**电视开机**

```
Boot / App 启动
  → 自检：令牌有效 → 无障碍 → 使用情况 → 通知权限 → 守护服务 → 网络
  → 全过：静默驻留（点开 App 才显示只读状态页）
  → 有失败项：只显示失败项的引导页
```

**观看判定（每 60 秒一轮，与现状一致）**

```
GET /v1/tv/context
  → quiz_enabled=false 且 limit_enabled=false → allowed
  → limit_enabled=true 且 used ≥ daily_limit → hard_stop（不可退出）
  → quiz_enabled=true 且 本次已看 ≥ unlock_minutes 且无可用授权 → 弹题
     ├─ quiz_scope=random：全库随机取题，忽略年级/难度
     └─ quiz_scope=grade ：按孩子「有效年级」映射 stage 取题
  → 其余 → 允许
```

**年级自动升级**

```
child_profile.grade_tag = 'g3'，grade_set_at = 2026-09-01
有效年级 = 3 + (今天 与 grade_set_at 之间跨过的 9 月 1 日次数)，封顶 g9
→ 2027-09-01 起自动变 g4，无需定时任务，读时计算
```

## 5. 数据模型

### 5.1 新增 `tv_device`

```sql
create table tv_device (
    id               uuid primary key default gen_random_uuid(),
    family_id        uuid not null references family (id) on delete cascade,
    child_id         uuid references child_profile (id) on delete set null,
    device_id        text not null,
    name             text not null default '电视',
    platform         text not null default 'tv',
    token_hash       text not null default '',
    token_expires_at timestamptz,
    last_seen_at     timestamptz,
    status           text not null default 'active',
    created_at       timestamptz not null default now(),
    constraint tv_device_status_chk check (status in ('active', 'revoked'))
);
create unique index tv_device_device_idx on tv_device (device_id) where status = 'active';
create index tv_device_family_idx on tv_device (family_id) where status = 'active';
```

> `device_id` 仍由客户端生成并持久化（现状 `DeviceIdentity` 已有），保证重装后能复用令牌。

### 5.2 新增 `tv_config`

```sql
create table tv_config (
    device_pk        uuid primary key references tv_device (id) on delete cascade,
    quiz_enabled     boolean not null default true,   -- 做题开关
    limit_enabled    boolean not null default true,   -- 上限开关
    unlock_minutes   integer not null default 15,     -- 多少分钟强制做题
    daily_limit      integer not null default 60,     -- 限制看多长时间
    subjects         jsonb   not null default '[]',   -- 空数组 = 所有题
    pass_threshold   numeric(6,2) not null default 3,
    quiz_scope       text    not null default 'random', -- random=不分难度 / grade=按孩子年级
    hard_stop_grace  integer not null default 10,     -- 硬停页「家长 PIN」放行分钟
    version          integer not null default 1,
    updated_by       uuid references parent_account (id) on delete set null,
    updated_at       timestamptz not null default now(),
    constraint tv_config_unlock_chk check (unlock_minutes between 1 and 240),
    constraint tv_config_daily_chk  check (daily_limit between 1 and 720),
    constraint tv_config_grace_chk  check (hard_stop_grace between 1 and 120),
    constraint tv_config_scope_chk  check (quiz_scope in ('random', 'grade'))
);
```

### 5.3 孩子档案增列

`quiz_session` / `watch_log` / `watch_grant` 的 `child_id` 均为 `not null`，共 81 处引用。为支持"电视不指定孩子"，**不改这三张表**，改为登录时自动创建一条**占位孩子**：

```sql
alter table child_profile
    add column is_placeholder boolean not null default false,
    add column grade_set_at   date;   -- 当前年级的起始日（升年级基准）
```

| 情况 | child_profile | 组卷 |
| --- | --- | --- |
| 未指定孩子 | 自动建一条 `is_placeholder=true`，昵称 = 电视名，家长端孩子列表**不显示** | `quiz_scope=random`，全库随机 |
| 指定孩子 | 家长输入昵称（默认值 = 电视名）+ N 年级，`is_placeholder=false` | `quiz_scope=grade`，按有效年级 |

年级 → 题库档位映射（题库只有四档，`stage_code` 约束为 `preschool/low/mid/high`）：

| 年级 | grade_tag | stage_code |
| --- | --- | --- |
| 学前 | null | preschool |
| 1–2 | g1/g2 | low |
| 3–4 | g3/g4 | mid |
| 5–9 | g5…g9 | high |

> 题库没有初中档，7 年级以上按高年级题出。等题库扩充再加 `junior` 档，届时只改映射表。

### 5.4 保留不变

- `watch_rule`：孩子级默认模板，仅在新建电视时作为复制来源。
- `device_bind`：旧版电视继续使用，标记 deprecated，下个版本再删。
- `watch_grant` / `watch_log` / `quiz_session`：不变；随机模式通过占位孩子满足外键，`quiz_scope` 决定选题策略。

迁移 `00033` 同时把现有 `device_bind`（active）复制成 `tv_device` + 默认 `tv_config`，保证旧电视升级后配置不丢。

## 6. 接口设计

### 6.1 电视端

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/v1/auth/sms/code` | 复用；请求体加可选 `client:"tv"`，用于分渠道限流 |
| POST | `/v1/tv/login` | **新增**。`{phone, code, device_id, device_name}` → `{device_token, expires_at, device{id,name}, config}` |
| GET | `/v1/tv/context` | **新增**。返回 `{allowed, reason, hard_stop, quiz_enabled, limit_enabled, remaining_minutes, daily_limit, unlock_minutes, next_quiz_minutes, rule_version}` |
| GET | `/v1/tv/me` | **新增**。设备名、家庭名、孩子名（可为空）、令牌到期时间 |
| PUT | `/v1/tv/capability` | 复用（仅 scope=device） |
| POST | `/v1/tv/heartbeat` | 复用现有 grant heartbeat 语义 |

`/v1/device/activate/code`、`/v1/device/token`、`/v1/family/devices/activate` 保留但标记 `deprecated: true`，供旧版电视在兼容期内使用。

### 6.2 家长端

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/v1/family/tvs` | **新增**。电视列表：名称、在线、今日已看、今日上限、两个开关状态 |
| GET | `/v1/family/tvs/{id}/config` | **新增**。读该电视配置（含 `quiz_scope`、`hard_stop_grace`） |
| PUT | `/v1/family/tvs/{id}/config` | **新增**。需家长 PIN；改完整配置，`version` 递增 |
| PUT | `/v1/family/tvs/{id}/child` | **新增**。`{nickname, grade}` 指定孩子；`{child_id:null}` 回到随机模式 |
| GET | `/v1/family/tvs/{id}/child` | **新增**。返回昵称、`grade_tag`、有效年级（自动升级后） |
| POST | `/v1/family/tvs/{id}/unlock` | 复用现有家长解锁，语义改为"放行 N 分钟" |
| DELETE | `/v1/family/tvs/{id}` | **新增**。解绑（吊销令牌） |

错误码沿用现有约定：`VALIDATION_ERROR`、`AUTH_INVALID_TOKEN`、`AUTH_DEVICE_UNBOUND`、`TV_CONFIG_NOT_FOUND`。

### 6.3 令牌作用域

设备令牌 JWT 增加 `scope: "device"`。中间件：

- `/v1/tv/**`、`/v1/device/**`：接受 `scope=device` 与 `scope=parent`
- `/v1/family/**`：仅接受 `scope=parent`，设备令牌返回 403 `AUTH_SCOPE_FORBIDDEN`

## 7. 非功能要求

| 项 | 要求 |
| --- | --- |
| 令牌有效期 | 365 天，剩余 < 30 天时电视静默续期（`POST /v1/tv/refresh`） |
| 配置下发延迟 | ≤ 60 秒（沿用 context 轮询周期） |
| 硬停恢复 | 检测到前台被切走 → 1 秒内重新拉起硬停页 |
| 自检耗时 | 开机自检 ≤ 2 秒，不阻塞答题与心跳 |
| 隐私 | 设备令牌无法读取家庭数据；日志不记录手机号明文（沿用 `maskPhone`） |
| 限流 | 短信 5 次/小时/号（沿用）；`/v1/tv/login` 10 次/小时/设备 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Android 无法真正阻止退出（Home 键是系统的） | 孩子能短暂逃出硬停页 | 无障碍服务 1 秒内重拉；文档明确这是"尽力而为"，彻底方案需 Device Owner |
| 家长误关"上限开关" | 当天完全不限时 | 家长端关闭时二次确认，文案写明"今天将不限时"；家庭日志留痕 |
| 电视登录后令牌被复制到其他设备 | 盗用观看额度 | 令牌绑定 `device_id`，服务端校验；同一账号异地登录提示家长端 |
| 旧版电视与新版并存 | 两套规则来源 | `device_bind` 路径保留并继续读 `watch_rule`；迁移脚本把已有绑定同步到 `tv_device` |
| 遥控器输入手机号体验差 | 首次登录放弃率高 | 数字键盘大按钮 + 记住上次手机号（本地明文仅存脱敏后 4 位）；扫码作为后续通道 |
| 孩子档案与电视多对一 | 报告归属不清 | `tv_device.child_id` 可为空；为空时报告归到"未指定孩子"分组 |

## 9. 未决问题

1. **电视删除后历史数据**：`watch_log` / `quiz_session` 是否保留？建议保留（报告要用），只吊销令牌。
2. **家庭内多家长同时改配置**：用 `version` 乐观锁，冲突时提示"配置已被修改，请刷新"。是否够用待确认。
3. **微信扫码**：需要开放平台资质 + 备案，暂缓；接口预留 `login_method` 字段。

已确认（2026-11-15）：硬停放行**按时长**且家长端可配（1–120 分钟，默认 10）；电视**不指定孩子**时全库随机不分难度；指定时输入**昵称（有默认值）+ N 年级**，每年 9 月 1 日**自动升年级**。
