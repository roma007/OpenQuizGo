## 1. 背景与目标

- 家长端目前按手机竖屏设计，平板/横屏下留白大、列表单列；
- 第 4 期先从「多端一致性」中成本最低的平板/横屏适配开始；
- 非目标：小程序、孩子端独立 App、会员/支付（后续单独设计）。

## 2. 断点

| 宽度 | 形态 | 导航 |
| --- | --- | --- |
| < 720 | 手机 | 底部 NavigationBar |
| 720–1099 | 大屏手机/小平板 | 底部导航 + 内容限宽 |
| ≥ 1100 | 平板/横屏 | 左侧 NavigationRail + 内容最大 1200 |

> 2026-11-12 起，iPad 导航与栅格规则由 [076](076-iOS与iPad适配设计.md) 修订：改为按最短边识别平板，iPad 全尺寸使用侧边导航；本文其余结论继续有效。

## 3. 页面调整

- 首页：宽屏用 NavigationRail；内容居中限宽；
- 孩子/设备：宽屏两列卡片网格；
- 报告：宽屏左右分栏（最新报告 + 历史）；
- 规则/PIN/成员/登录：表单限宽 720–900；
- 诊断/告警：列表限宽 1000。

## 4. 验收

- 手机尺寸布局不回归；
- 横屏 1920×1200 下出现侧边导航、列表/卡片多列；
- Widget 测试覆盖宽屏断点。

## 5. 风险

| 风险 | 对策 |
| --- | --- |
| 宽屏内容拉得过长 | 统一 maxWidth |
| 小屏回归 | Widget 测试保留手机尺寸用例 |
| 刘海/安全区 | SafeArea 保留 |
