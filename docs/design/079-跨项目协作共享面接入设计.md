## 1. 背景与目标

- 现状与问题：
  - OpenChronicleAtlas 与 OpenQuizGo 共用一台 ECS、一个 nginx 容器（`quizgo-web-1`）、一份磁盘，此前跨项目协调靠用户在两个 AI 之间传话。
  - 传话导致三类故障：状态滞后（以为配置已生效）、双写冲突（同时改 `/srv/nginx`）、静默漂移（有人手改服务器另一头不知道）。
  - 服务器已建成 `/srv/ops/` 共享面（`CONTRACT.md`、`bin/status.sh`、`bin/inbox.sh`、`state/`、`journal/`、`requests/`、`locks/`），Atlas 侧已接入；QuizGo 侧尚未接入，`state/quizgo.json` 仍是 Atlas 初始化的占位数据。
  - 另有一条遗留 P2：`deploy.sh` 在 `docker compose build` **之前**写 `.env APP_VERSION`。构建失败（2C2G 全量约 5 分钟，OOM/拉依赖都可能挂）会留下「`.env` 新版本 + 镜像旧版本」，之后任一 `docker compose up -d` 就变成「报新版本、跑旧代码」。
- 本次目标（可验证）：
  1. 把「读 inbox」挂到必经路径：pre-commit 提示、`deploy.sh` 硬闸门、发布自检跑 `status.sh`。
  2. 发布收尾自动登记 `state/quizgo.json` 与 `journal/YYYY-MM.log`。
  3. `AGENTS.md` 增加 §9「跨项目协作」，写明锁、登记、日志、请求四条。
  4. 修正 `.env` 写入顺序：构建成功后再写版本。
  5. 用可证伪的方式验证：临时写坏 Go 代码 → 完整发布构建失败 → `.env` 与 `/v1/meta` 都停在上一版。

## 2. 需求与验收标准

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| R1 | 提交时能看到未处理请求 | pre-commit 输出 inbox(quizgo) 的 open 请求；`ssh` 不可达/超时 3 秒时静默跳过；**永不阻塞提交** | P0 |
| R2 | 发布前硬拦 | `deploy.sh` 开头有 open 请求 → `exit 2`；显式 `--ack-open` 才放行；共享面不可达时降级为告警不拦截 | P0 |
| R3 | 发布自检覆盖共享面 | 发布末尾跑一次 `/srv/ops/bin/status.sh`，出现 `⚠️` 只告警、不影响发布结果 | P1 |
| R4 | 发布收尾自动登记 | 覆盖 `state/quizgo.json`（version/commit/image + nginx 三文件 md5），追加一行 journal；登记失败不影响退出码 | P0 |
| R5 | 文档固化 | `AGENTS.md` §9 写明：动 `/srv/nginx/**` 或重启 web 前读 CONTRACT + `flock /srv/ops/locks/nginx.lock`；发布后覆盖 state；追加 journal；需要 Atlas 做事走 requests | P0 |
| R6 | `.env` 顺序 | `compose build` 成功后才写 `APP_VERSION`；构建失败时 `.env` 与 `/v1/meta` 停在上一版；`--skip-build` 分支行为不变（先写 `.env` 再 `up -d --force-recreate api worker`） | P0 |

## 3. 方案对比与选型

### 3.1 inbox 闸门放在哪里

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| 只写 AGENTS.md | 靠自觉，等于没解决 | 否 |
| 只在 pre-commit 提示 | 提交频繁，提示会被忽略；且发布不一定紧接提交 | 不足 |
| pre-commit 提示 + deploy 硬拦 + 自检 | 与 Atlas 侧一致，覆盖面最全 | **采用** |

### 3.2 pre-commit 是否阻塞

请求可能在对方挂几天，阻塞提交会让人被迫用 `--no-verify`，反而破坏钩子权威性。**只提示不阻塞**，与 Atlas 侧一致。

### 3.3 登记失败是否影响发布

发布已经完成并自检通过，此时 `/srv/ops` 写失败（磁盘满、权限）不应把一次成功发布判成失败，否则会诱发不必要的回滚。**登记失败只告警**，并在 terminal 明确提示手工补登。

### 3.4 `.env` 写入位置

| 方案 | 失败后果 | 结论 |
| --- | --- | --- |
| 保持现状（构建前写） | 构建失败 → `.env` 新版本 + 镜像旧版本 | 否 |
| 构建后写、`up -d` 前写 | 构建失败 → `.env` 保持旧版本，一致 | **采用** |
| 构建后、`up -d` 后写 | 容器已用旧版本启动，随后 `.env` 变新，自检会误判 | 否 |

`--skip-build` 分支没有构建步骤，保持「先写 `.env` 再 `up -d --force-recreate api worker`」。

## 4. 总体架构

```
本地提交 ──pre-commit──> 自增版本 + 列出 inbox(quizgo)（不阻塞）
                                   │
scripts/deploy.sh ──闸门──> inbox(quizgo) 有 open → exit 2，除非 --ack-open
        │
        ├─ 1  回滚点
        ├─ 2  备份
        ├─ 3  rsync
        ├─ 5a --with-nginx（备份 → 漂移 → 同步 → nginx -t → reload）
        ├─ 5b --with-units
        ├─ 6  build ──成功──> 写 .env ──> up -d
        │         └──失败──> 直接退出，.env 不动
        ├─ 7  自检（版本 / 镜像 ID / 状态 / 日志）
        └─ 8  /srv/ops 登记（state/quizgo.json + journal）+ status.sh 漂移自检
```

## 5. 数据模型

### 5.1 `state/quizgo.json`

```json
{
  "project": "quizgo",
  "updatedAt": "2026-11-14T18:20:00+08:00",
  "updatedBy": "quizgo-ai",
  "release": {
    "version": "1.0.16",
    "commit": "<40 位 sha>",
    "image": "sha256:<image id>"
  },
  "nginxMd5": {
    "nginx.conf": "<md5>",
    "conf.d/atlas.conf": "<md5>",
    "conf.d/quiz.conf": "<md5>"
  }
}
```

- `nginxMd5` 必须三个文件齐全，否则 `status.sh` 无法检出该部分漂移。
- `image` 取 `docker image inspect openquizgo:local --format '{{.Id}}'`。
- 只写 `state/quizgo.json`，**不动 `state/atlas.json`**。
- 每次发布整体覆盖（幂等），不追加。

### 5.2 journal 行

```
2026-11-14T18:20:00+08:00 [quizgo] deploy | quizgo 1.0.16 | image sha256:… | ok
```

类别：`deploy` / `nginx` / `request` / `incident` / `ack` / `note`。只追加，不改写历史行。

## 6. 接口设计

### 6.1 `deploy.sh` 新增参数

| 参数 | 行为 |
| --- | --- |
| `--ack-open` | 跳过 inbox 闸门（仅用于「已确认 open 请求与本次发布无关」或本次发布就是为处理这些请求） |

闸门行为：

- `inbox.sh quizgo` 输出含 `⬜` → 打印请求清单并 `exit 2`。
- 输出不含 `⬜`（含「没有未处理请求」）→ 放行。
- `ssh`/脚本不可达（输出为空）→ 打印提示后放行，避免共享面故障变成发布单点。

### 6.2 收尾登记

- 在自检通过、`.deployed-image` 写入之后执行。
- `set -e` 环境下属「失败不影响发布结果」：函数在 `if` 条件中调用，显式 `|| return 1`，外层只告警。
- `--dry-run` 不写任何东西。

## 7. 非功能要求

- **可重入**：重复执行 `deploy.sh` 结果一致；`state/quizgo.json` 覆盖写，journal 每次一行。
- **不阻塞**：pre-commit 最坏增加 3 秒（连接超时），失败静默。
- **单向依赖**：只读 Atlas 的 `state/atlas.json`，绝不写入；`/srv/nginx/**` 写入前仍由 `--with-nginx` 的备份/回滚保护。
- **安全**：不把 `.env`、密钥写入 `state/` 或 journal。

## 8. 风险与对策

| 编号 | 风险 | 影响 | 对策 |
| --- | --- | --- | --- |
| R1 | 共享面不可达导致发布被堵死 | 无法发布 | 只在「读到明确 open 请求」时拦截；读不到降级为提示 |
| R2 | pre-commit 因 ssh 卡住 | 提交变慢 | `BatchMode=yes` + `ConnectTimeout=3` + `|| true` |
| R3 | 登记脚本在 `set -e` 下中断发布 | 成功发布被判失败 | 函数在 `if` 条件中调用，内部 `|| return 1`，外层 catch |
| R4 | nginx md5 少记导致漏检漂移 | 漂移检测不完整 | 三文件不足 3 行时登记失败并告警 |
| R5 | 构建失败仍写 `.env` | 「报新版本跑旧代码」 | `.env` 写入后移到 build 成功之后，并用写坏 Go 代码实测 |
