## 1. 背景与目标

### 1.1 现状与问题

- **077（2026-11-12，`eb2c728`）把 TV 端改成纯本地单机**：一次删除 54 个文件、净删 4489 行，
  移除 Retrofit/OkHttp、`GuardApi`（348 行）、`GuardEngine`（566 行）、`QuizRepository`、
  `WatchRepository`、`TokenCipher`、`BlockerActivity`、`BattleActivity` 等，同时移除
  `INTERNET` / `ACCESS_NETWORK_STATE` 权限。
- 现在 TV 端只有一个本地资产题库 `assets/questions.json`（120 题）、DataStore 里 3 个键
  （`quiz_enabled` / `elapsed_seconds` / `last_question_id`）和一份本地 `guard.log`，
  **不发任何网络请求**。
- 077 的动因是当时「服务器和域名未准备、家长端暂停推进、开发库只有测试题」，
  并明确写明「旧服务端代码保留在 Git 历史中，后续需要时再恢复」——即阶段性回退，不是终局架构。
- **现在条件已经变了**：
  1. 服务端、数据库、对象存储、管理端题库（审核/发布/覆盖率/校准）全部完成并在运行；
  2. 域名 `quiz.openapp.asia` 已解析，服务经 nginx 8082 对 Tailscale 网段提供；
  3. **为了上架苹果市场，账号/家庭/规则/报告必须走服务端**，否则 App Store 侧无法说明守护能力与数据来源。
- 后果：TV 端现在是「孤立单机」——家长端看不到、管不了，服务端 `/v1/device/*`、`/v1/quiz/sessions*`、
  `/v1/watch/*`、`/v1/offline/lease` 等整组接口在真实设备上**空转**。

### 1.2 本次目标（可验证）

1. TV 端完成激活绑定后，**所有业务数据以服务端为唯一真源**：规则、额度、题目、判分、授权、计时对账。
2. 规则 100% 来自服务端 `Rule`（`unlock_minutes` / `daily_limit` / `time_window` / `scope_mode`
   / `allowed_apps`），TV 端**不再有硬编码的「15 分钟」**。
3. 题目与判分只在服务端：TV 不打包题库，`assets/questions.json` 删除。
4. 家长端修改规则后，TV 在 **≤ 60 秒**内生效，无需重启或重装。
5. 保留 077 沉淀下来的可靠件：`MediaPlaybackDetector`（媒体播放检测）、`GuardService`（前台服务
   + 看门狗）、`LogStore`（滚动日志）、端口化可测试结构。

### 1.3 非目标（明确不做什么）

- 不新增对战功能；072/073 已完成的代码随恢复原样保留，本期不在此之上继续开发。
- 不恢复会员、支付、发票。
- 不做 TV 端家长账号登录（TV 只有设备令牌，账号体系留在家长端）。
- 不做题库在线热更新到本地（每轮开题由服务端下发，TV 不缓存题目）。
- 不改动服务端接口与家长端 UI（现有接口已满足；若实施中发现确实要加，须回写本文档）。

## 3. 方案对比与选型

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 直接 `git revert eb2c728` | 最快拿回服务端实现 | 077 之后 `MainActivity`/`QuizActivity`/`GuardService` 已重写，冲突面极大；会丢掉 `MediaPlaybackDetector` 与端口化测试结构 | 否决 |
| B. **保留 077 的「薄壳」骨架，替换数据源** | 复用 tick 循环、媒体检测、看门狗、日志；改动集中在数据层与状态机；新旧代码可直接对照 Git 历史 | 需要新写 `RemoteGateway` 与状态机分支，工作量中等 | **采用** |
| C. 双轨可切换（本地模式 / 服务端模式） | 断网、无服务器时也能用 | 两套状态机并存易误触（077 已论证）；上架审核中含隐藏本地模式存在合规风险 | 否决 |
| D. 新建 TV 工程 | 隔离彻底 | 复制权限/无障碍/媒体检测等成熟代码，维护两份 | 否决 |

**选型理由**：077 已经证明「薄壳 + 端口注入」这个结构是好用的（`LocalGuardEngine` 只依赖
`LocalSettingsStore` + `PlaybackSource` 两个端口，单测可直接注入假实现）。080 只需把这个引擎的
数据源从「本地计时」换成「服务端 context + 授权」，其余骨架原样留用，风险与工作量都最小。
方案 C 被否决的关键理由与 077 相同：本项目不允许存在一条绕过服务端管控的路径。

> **实施偏差（2026-11-15，已批准）**：实际执行时发现 `eb2c728^` 的服务端实现（TV 0.4.4）
> 本身完整且带 18 个可运行单测，逐文件重写反而更容易引入回归。因此实施方案 B 的具体做法改为：
> **整目录从 `eb2c728^` 恢复 `tv/app/src/main/java/.../guard`，再增量叠加 077 之后仍然有价值的改动
> （开机自启、BootstrapActivity、无界面初始化）并与 080 的新需求（`/v1/child/context`）合并**。
> 架构结论与目标不变，只是「恢复」优先于「重写」。

### 4.2 状态机

```
UNBOUND ──激活成功──> IDLE
IDLE ──媒体开始播放──> WATCHING
WATCHING ──context.remaining<=0 或 time_window 外──> BLOCKED
WATCHING ──服务端判定该答题──> QUIZ_REQUIRED
QUIZ_REQUIRED ──拉起答题──> QUIZZING
QUIZZING ──答对且达到 pass_threshold──> GRANTED ──授权耗尽──> WATCHING
QUIZZING ──答错──> QUIZZING（锁定，直到答对）
BLOCKED ──家庭 PIN 解锁成功──> GRANTED
任一状态 ──令牌 401──> UNBOUND
```

与 077 的差异：`elapsed_seconds` 不再是触发器，只作为「本地兜底显示」的近似值；
真正的判定输入是 `context`（`allowed` / `reason` / `remaining_minutes`）与授权对象。

### 4.3 关键流程

**激活**
1. TV 开机 → 无令牌 → `ActivationActivity`
2. `POST /v1/device/activate/code`（`device_id` + `platform=tv`）→ 展示 6 位码
3. 家长端输入码 + 选孩子 → `POST /v1/family/devices/activate`
4. TV 轮询 `POST /v1/device/token`：202 继续等，200 拿到令牌 → `TokenCipher` 加密存盘 → 进 IDLE

**观看与计量**
1. `MediaPlaybackDetector` 检测到播放 → `GET /v1/watch/grants/active`
2. 有授权 → 播放中每 60s `heartbeat`；无授权 → `GET /v1/child/context`
3. `context.remaining_minutes <= 0` 或 `reason != ok` → BLOCKED
4. 否则维持 WATCHING，每分钟刷新一次 context（保证家长改规则 ≤60s 生效）

**答题**
1. `POST /v1/quiz/sessions` → 返回题目与 `pass_threshold`、`expires_at`
2. 逐题 `POST /answers`（错误反馈由服务端给，不本地判分）
3. `POST /finish` 达到阈值 → 服务端签发授权 → GRANTED，计时重新开始
4. 409 `QUIZ_SESSION_ACTIVE` → 直接复用已有会话，不重复创建

**断网降级**
1. 在线且允许时预取 `GET /v1/offline/lease`（Ed25519 签名，含 `max_minutes`）
2. 断网 → 校验签名与绝对过期 → 只允许消耗租约分钟数；**不能开答题会话**
3. 恢复网络 → `POST /v1/watch/logs` 上报条目，服务端扣减当日额度

## 5. 数据模型

TV 端本地只保留最小状态，**业务数据一律不落盘**。

| 键（DataStore `guard`） | 类型 | 说明 |
| --- | --- | --- |
| `device_token_enc` | String | AES-GCM 密文（Keystore 别名 `guard_token`） |
| `device_id` | String | 本地生成的稳定设备标识 |
| `child_id` | String | 绑定返回的孩子 ID |
| `token_expires_at` | Long | 令牌过期时间，用于提前刷新 |
| `rule_version` | Long | 便于判断规则是否变化 |
| `last_context_at` | Long | 上次成功拉取 context 的时间 |
| `lease_json` | String | 离线租约原文 + 签名 |
| `pending_offline` | String | 待补报的观看条目（JSON 数组） |
| `pending_quiz_session` | String | 未完成会话 ID，用于断点续答 |

- 迁移策略：`LocalSettings` 的三个键全部弃用；升级后首次启动视为未绑定（无令牌），走激活流程。
- 不建索引与约束（无数据库）。
- `assets/questions.json` 删除后 APK 体积减少约 33KB。

## 6. 接口设计

全部为**已有接口**，本期不新增服务端代码。

| 类型 | 名称 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- | --- |
| POST | `/v1/device/activate/code` | `device_id`, `platform=tv` | 6 位激活码 | 免鉴权 |
| POST | `/v1/device/token` | `code`, `device_id` | 令牌 / 202 等待 | 免鉴权，轮询 |
| GET | `/v1/child/context` | — | `allowed`,`reason`,`rule`,`rule_version`,`daily_limit`,`used/reserved/remaining_minutes`,`now` | **规则与额度的唯一来源** |
| POST | `/v1/quiz/sessions` | — | `session_id`,`expires_at`,`pass_threshold`,`questions[]` | 已有 3 次/10 分钟限流 |
| POST | `/v1/quiz/sessions/{id}/answers` | `item_id`,`answer[]`,`elapsed_ms` | 是否正确 + 解析 | 判分只在服务端 |
| POST | `/v1/quiz/sessions/{id}/finish` | — | 是否达标 + 授权 | 达标才签发 |
| GET | `/v1/watch/grants/active` | — | 授权或 404 | |
| POST | `/v1/watch/grants/{id}/heartbeat` | `foreground_app`,`paused`,`position_seconds` | 计量结果 | 60s 一次 |
| GET | `/v1/offline/lease` | — | 签名租约 | 预取 |
| POST | `/v1/watch/logs` | `lease_id`,`entries[]` | 对账结果 | 恢复网络后 |
| POST | `/v1/device/unlock` | `pin`,`minutes` | 授权 | 403 PIN 错 / 429 频率 |
| PUT | `/v1/device/capability` | 守护模式、权限状态 | — | 启动与变化时 |
| POST | `/v1/device/tamper` | 异常类型 | — | 权限被关等 |
| POST | `/v1/device/diagnostics` | `content`(≤256KB),`note` | — | 手动上传 |
| GET | `/v1/device/me` | — | 设备信息 | 校验令牌有效性 |
| DELETE | `/v1/device/me` | — | — | 换绑前重置 |

**错误约定**：`401` → 清令牌回 UNBOUND；`403` → 设备已解绑，提示重新绑定；`409 QUIZ_SESSION_ACTIVE`
→ 复用会话；`429` → 指数退避（30s/60s/120s，上限 5 分钟）并保持当前状态，不静默放行。

## 7. 非功能要求

- **性能**：单台 TV 稳态请求量约 1 次/60s（心跳 + context 交替）。按 1000 台在线估算约 17 rps，
  单请求 <20ms，服务端 2C2G 可承载；实测 p95 超过 300ms 需评估加索引或合并接口。
- **安全**：令牌 Keystore 加密、不打印；HTTPS 为硬要求（备案前只能经 Tailscale 访问，见风险表）；
  服务端已具备限流（会话创建、心跳、PIN 都有阈值）。
- **可观测性**：`guard.log` 记录状态迁移与网络结果（脱敏，不含令牌）；服务端 `/metrics` 已有会话与心跳指标；
  诊断上传用于线上排障。
- **兼容性**：与 1.0.23 本地版**不兼容**，属破坏性变更，需升大版本语义（仍按铁律 3 走 1.0.X 自增，但
  `versionCode` 连续递增即可升级覆盖）；`capability` 上报中带版本号，便于服务端识别旧端。

## 8. 风险与对策

| 风险 | 影响 | 概率 | 对策 |
| --- | --- | --- | --- |
| **备案未通过，家庭电视连不上服务器**（nginx 只放行 `127.0.0.1` 与 `100.64.0.0/10`，安全组已删 80/443） | 交付后真实家庭装上去无法激活，等于不可用 | **高** | 本期先定位为「内测版」：Tailscale 共享节点或临时放行指定出口 IP；备案通过后再对外。TV 首屏必须有明确的「连不上服务器」文案与重试 |

| 无障碍被系统杀死 | 拦截失效 | 中 | 保留 077 的看门狗与自启；`tamper` 上报，家长端告警 |
