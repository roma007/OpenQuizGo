## 1. 背景与目标

### 现状与问题

家长端的通过标准是「加权门槛」：每道题按学科权重计分（数学 1.5、趣味 0.5 等），加权总分达到门槛才算通过。家长看不懂，而且「几分」无法对应到「答对几题」。

用户明确要求：**通过标准应该是答对多少道题，而不是得多少分。**

### 本次目标

- G1 家长端「孩子规则」与「电视设置」都改为配置 **答对几题算通过**（整数）。
- G2 服务端按 **答对题数** 判定通过：`correct_count >= pass_questions`。
- G3 默认答对 2 题（1 题场次为 1 题），且不超过本次题量。
- G4 保留加权分计算用于报告与判分明细，但不再作为通过依据。
- G5 存量数据自动回填，旧电视与旧会话不报错。

### 非目标

- 不改题库、判分（单题对错）、组卷学科占比。
- 不删除 `pass_threshold` 字段，暂作为组卷题量与历史兼容用途。

## 2. 需求与验收标准

| 编号 | 需求 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| R1 | 家长端配置答对题数 | 规则页/电视设置页显示「答对几题算通过」 | P0 |
| R2 | 按题数判定 | 答对 2 题即通过，与题目学科权重无关 | P0 |
| R3 | 不超过题量 | 1 题场次只能要求答对 1 题；配 5 题可要求 1–5 题 | P0 |
| R4 | 默认值 | 新电视/新规则默认答对 2 题（1 题场次为 1） | P0 |
| R5 | 存量兼容 | 迁移回填；旧家长端不传字段时沿用原值 | P1 |
| R6 | 电视端展示 | 答题结果页显示「答对 X / N 题 · 通过需要 Y 题」 | P1 |

## 3. 数据模型

- `watch_rule.pass_questions integer not null default 2`（1–12）
- `tv_config.pass_questions integer not null default 1`（1–12，运行时不超过 `question_count`；多题场次家长端默认填 2）
- `quiz_session.pass_questions integer not null default 2`（快照）
- 存量：`tv_config.pass_questions = least(2, question_count)`；其余默认 2。

## 4. 接口

- `Rule` / `TVConfig` 新增 `pass_questions`。
- `CreateSessionResponse`、`AnswerResult`、`SessionSummary` 新增 `pass_questions`；`pass_threshold` 保留。
- 校验：`1 ≤ pass_questions ≤ 每次题量`，否则 422。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 难度变化 | 原来按分数，现在按题数 | 默认 2 题，接近原默认门槛；家长可调 |
| 趣味题被计入 | 可能靠趣味题通过 | 保持趣味题上限较低（默认 2） |
| 旧客户端不传字段 | 被重置 | 0 视为未提供，沿用库中原值 |
