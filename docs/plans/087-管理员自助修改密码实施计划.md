## 1. 目标与范围

- 交付目标：后台自助改密，改密后全部会话立即失效。
- 范围边界：`internal/admin`、`cmd/admin`、`admin-web` 顶栏与弹窗、`api/openapi.yaml`；不动登录契约、RBAC、数据库结构。
- 前置条件：Redis 可用（线上已具备）；`REDIS_URL` 在 `.env` 中（CLI 也读它）。

## 4. 验证方式

- 单元测试：口令规则表驱动；`sign`/`parse` epoch 往返；限流键命名。
- 集成/端到端（本地 `make dev`）：
  1. 正确旧口令改密 → 200，Cookie 被清，跳登录。
  2. 新口令 = 旧口令 → 422。
  3. 新口令 7 位 → 422；73 字节 → 422。
  4. 旧口令连错 5 次 → 第 6 次 429。
  5. 两个浏览器同时登录，A 改密后 B 的 `/v1/admin/me` → 401。
- 线上：部署后用真实账号走一次（改成一个临时口令，再改回），确认旧会话失效、`/v1/meta` 版本对齐。

## 5. 回滚方案

| 场景 | 动作 | 耗时 |
| --- | --- | --- |
| 后端异常 | `docker tag openquizgo:rollback openquizgo:local && docker compose up -d --no-build` | < 2 分钟 |
| 前端异常 | `rsync` 上一版 `admin-web/dist` | < 1 分钟 |
| epoch 逻辑导致全员 401 | 回滚镜像即恢复（Redis 键残留无害） | < 2 分钟 |

数据影响：无迁移、无表结构变化；仅 Redis 两个键。

## 6. 决策记录

| 时间 | 决策 | 理由 |
| --- | --- | --- |
| 2026-11-23 | 用 Redis epoch 而非 DB 列 | 管理端请求少但要求立即失效；避免每请求查库与迁移 |
| 2026-11-23 | 改密后全量失效，不做「仅当前会话」 | 泄露场景下部分失效没有意义 |
| 2026-11-23 | 新口令下限 12 个字符、上限 72 字节 | 与 CLI 对齐；Atlas 请求也建议 12；bcrypt 上限 72，超出必须显式拒绝 |
