## 3. 验证方式

### 3.1 静态检查

```bash
bash -n scripts/deploy.sh
sh -n scripts/git-hooks/pre-commit
./scripts/deploy.sh --dry-run            # 有 open 请求时应 exit 2
./scripts/deploy.sh --ack-open --dry-run # 应打印完整步骤
```

### 3.2 闸门测试

- 保留两条 open 请求时跑 `deploy.sh --dry-run` → `exit 2` 并列出请求。
- 加 `--ack-open` → 放行。
- 把 `ssh` 指向不存在的 host（`SSH_HOST=nonexistent ./scripts/deploy.sh --dry-run`）→ 只告警不拦截。

### 3.3 `.env` 顺序（能证伪）

1. 线上停在 1.0.15。
2. 临时写坏一个 `.go` 文件（语法错误）。
3. 跑一次完整发布：`scripts/deploy.sh --ack-open`。
4. 断言：构建失败、脚本非 0 退出；`/srv/quizgo/.env` 仍为 `APP_VERSION=1.0.15`；`/v1/meta` 仍为 1.0.15。
5. `git checkout -- <坏文件>` 还原。

### 3.4 线上验收

```bash
ssh quizgo '/srv/ops/bin/inbox.sh quizgo'   # ✅ 没有未处理请求
ssh quizgo '/srv/ops/bin/status.sh'         # 无 ⚠️
ssh quizgo 'cat /srv/ops/state/quizgo.json' # updatedBy=quizgo-ai，三文件 md5 齐全
ssh quizgo 'tail -5 /srv/ops/journal/2026-11.log'  # 至少一行 [quizgo]
```

## 5. 回滚方案

- 代码回滚：`git revert <提交>` 或 `git reset --hard v1.0.15`；`deploy.sh --skip-build` 恢复线上版本号。
- 线上镜像回滚：`ssh quizgo 'docker tag openquizgo:rollback openquizgo:local && cd /srv/quizgo && docker compose up -d --no-build'`。
- 共享面登记回滚：`state/quizgo.json` 是覆盖写，重跑一次成功发布即可恢复；journal 只追加，不删历史行。
