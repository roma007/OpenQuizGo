## 1. 目标与范围

- 交付目标：电视端改为手机号 + 验证码登录；配置全部收到家长端并按电视下发；开机自检按项引导；每日上限到点硬停。
- 范围边界：
  - 包含：服务端登录/配置接口与迁移、家长端电视列表与设置页、电视端登录页/自检页/只读状态页/硬停页、按设备组卷。
  - 不包含：微信扫码实装、Device Owner 管控、孩子档案改造、题库与判分逻辑变更。
- 前置条件：080 已合并（`/v1/child/context`、`GuardEngine` 服务端判定、拦截页自动退出均已具备）。

## 4. 验证方式

- 单元测试：`make test`；新增 `internal/identity` 登录用例、`internal/rule` 配置隔离用例、`internal/watch` 硬停判定用例。
- 集成测试：`make test-int`（需 `TEST_DATABASE_URL` / `TEST_REDIS_URL`）。
- 客户端：`./gradlew :app:testDebugUnitTest`、`pnpm --filter admin-web build`、`flutter analyze`（家长端）。
- 端到端：本机 AVD + 本地 API（SMS mock）；两台模拟设备共用同一账号，验证配置互不影响。
- 回归：080 已验收的 9 项（激活→计量→答题→授权→拦截）中，除"激活"外全部保持通过。

## 5. 风险与回滚

- 回滚方式：
  - 代码：回到 081 合并前的 tag，`docker compose up -d --no-build`。
  - 数据：`00033` 只新增表并复制数据，不删列；回滚代码后旧表仍在，旧版电视继续工作。
- 风险点：
  1. 硬停页在部分机型（创维）可能被系统限制后台启动 → 需要真机验证，失败时降级为"拦截页 + 通知"。
  2. 电视登录依赖短信，线上 `SMS_MODE=disabled` → 发布前必须开通短信通道，否则新电视无法登录。
  3. 家长端"下线绑定电视"会影响已有用户 → 保留旧入口到 082 再移除。

## 6. 决策记录

| 日期 | 决策 | 原因 |
| --- | --- | --- |
| 2026-11-15 | 用手机号 + 验证码登录替代激活码绑定 | 用户要求所有客户端都注册登录；前端输入一次即可长期免登录 |
| 2026-11-15 | 配置按电视（新增 `tv_config`），`watch_rule` 降级为默认模板 | 用户要求每台电视分别配置 |
| 2026-11-15 | 两个开关独立（做题 / 上限） | 用户明确"各管各的" |
| 2026-11-15 | 电视端不保留任何配置页 | 用户要求配置全部收到家长端 |
| 2026-11-15 | 硬停做"全屏 + 禁返回 + 1 秒重拉"，不承诺物理不可退出 | Android 系统限制；彻底方案需 Device Owner |
| 2026-11-15 | 硬停放行按时长，家长端可配 1–120 分钟（默认 10） | 用户确认 |
| 2026-11-15 | 未指定孩子时用"占位孩子"而非把 `child_id` 改可空 | 三张表 81 处引用，改可空风险大；占位孩子只多一列且不动外键 |
| 2026-11-15 | 未指定孩子时全库随机取题，不分年级/难度 | 用户指定 |
| 2026-11-15 | 指定孩子时输入昵称（默认值）+ N 年级，每年 9 月 1 日自动升年级 | 用户指定；读时计算，无需定时任务 |
| 2026-11-15 | 微信扫码本期不做 | 需开放平台资质 + 备案域名 |
| 2026-11-15 | 默认 15 分钟 / 60 分钟 / 全部题目 | 用户指定默认值，与迁移 `00032` 一致 |
| 2026-11-15 | 做题关闭时用 `POST /v1/tv/meter` 计量，不复用 `watch_grant` | 没有答题授权就没有心跳写 `watch_log`，额度永远不增长；计量接口写日志并回传最新 context，语义独立且不用迁移 |
