## 1. 目标与范围

- 交付目标：家长端按电视配置每次答题题量（1–5 题，默认 1）；服务端按配置精确组卷，并保证门槛可达；存量电视保留原题量。
- 范围边界：
  - 包含：迁移、`TVConfig` 字段与校验、组卷题量、门槛保底、家长端设置项、接口契约、测试。
  - 不包含：孩子规则页改动、非电视设备题量、电视端 UI、判分与题库逻辑。
- 前置条件：081 的 `tv_config` 与家长端电视设置页已上线。

## 4. 验证方式

- 单元测试：`go test ./internal/rule/... ./internal/quiz/...`；新增题量校验、门槛保底、精确题量用例。
- 集成测试：`make test-int`（需 `TEST_DATABASE_URL` / `TEST_REDIS_URL`），覆盖迁移回填后读取与组卷。
- 客户端：`cd parent && flutter analyze && flutter test`。
- 手工验收：两台模拟电视分别设 1 题 / 5 题 → 各自创建会话题量正确；改回 3 题后 60 秒内生效。

## 5. 回滚方案

- 触发条件：组卷题量异常或旧客户端保存配置导致题量丢失。
- 回滚步骤：回滚代码到 082 之前的 tag，`docker compose up -d --no-build`；`00034` 只新增列，旧代码忽略该列，无需回库。
- 数据兼容性：`question_count` 有默认值，旧代码读写不受影响。
