## 1. 目标与范围

- **交付目标**：TV 端从「本地单机」切回「服务端为唯一真源」，重新具备激活绑定、规则下发、
  服务端出题判分、观看计量、额度拦截、家庭 PIN 解锁、离线租约降级与诊断上报。
- **范围边界**：仅 `tv/` 与相关文档；**不改服务端接口**（现有 `/v1/device/*`、`/v1/quiz/sessions*`、
  `/v1/watch/*`、`/v1/offline/lease` 已满足），不改家长端、管理端。
- **前置条件**：
  1. 设计 080 状态为 `approved`；
  2. Android SDK 35 + JDK 17 + Gradle 可构建（与 077 一致）；
  3. 有一个可连的服务器环境（当前 Tailscale `http://quizgo-ecs:8082`）；
  4. 家长端账号下至少有 1 个孩子与默认规则。

## 4. 验证方式

- **单元测试**：`./gradlew test`
  - `ServerGuardEngineTest`：状态迁移、401 降级、额度耗尽、答错锁定
  - `TokenCipherTest`：加解密往返、密文不含明文
  - `GuardPreferencesTest`：重启后恢复绑定与租约
  - `ApiFactoryTest`：baseUrl 解析、401 拦截
- **集成/端到端**：本地起服务端（`make dev`）或连 Tailscale 上的线上服务；
  用家长端（或 `curl` 模拟家长令牌）完成绑定，TV 端跑完整一轮。
- **手工验收步骤**：
  1. 卸载重装 → 首屏出 6 位码；
  2. 家长端输入码并选孩子 → TV 30s 内进入首页，显示剩余额度；
  3. 播放视频 → 后台每分钟一次心跳，服务端 `used_minutes` 增长；
  4. 家长端把 `daily_limit` 改为 1 分钟 → TV 60s 内进入拦截界面；
  5. 答题：答对 → 授权 `unlock_minutes` 分钟可继续；答错 → 停留在原题；
  6. 拦截界面用家庭 PIN 解锁 → 拿到授权；
  7. 拔网线 → 只能看租约剩余分钟；恢复网络 → 服务端记录对账；
  8. 家长端解绑设备 → TV 下次请求 403，回到激活页。

## 5. 回滚方案

- **触发条件**：M1/M2 验收中出现无法在当轮修复的阻断问题（例如服务端接口与预期不符、
  真机无法激活），且需要恢复可用性。
- **回滚步骤**：
  1. 代码：`git revert` 本计划的提交，恢复到 1.0.23 的本地单机形态；
  2. APK：重新构建并覆盖安装（`versionCode` 递增，需卸载重装可接受）；
  3. 数据：TV 端本地无业务数据，回滚不涉及数据库；服务端不受影响（未改接口）。
- **数据兼容性**：服务端零改动，回滚无数据风险；TV 端本地绑定信息随版本回滚失效，需重新激活。

## 7. 验收结论

- 结论：**部分通过**。单测（18 项）、Debug/Release 构建、服务端激活接口冒烟均通过；
  真机端到端（家长端绑定 → 计量 → 弹题 → 授权 → 拦截 → 解锁）与迁移 `00032` 的实际执行待验。
- 遗留问题：
  1. 需在接入 tailnet 的电视上完成真机验收（备案前只有内网可达）。
  2. `migrations/00032_watch_rule_default_unlock_15.sql` 需随下次服务端发布执行，本地无 PG 无法预验。
  3. 旧版 1.0.23（本地单机版）与新版的边界：旧版不会再上报数据，需引导升级。
- 后续建议：备案通过后，用 `-PapiBaseUrl=https://quiz.openapp.asia/` 重新构建并对外发布；
  真机验收通过后再把本文档状态改为 `done` 并在 `docs/ROADMAP.md` 勾选 080。
