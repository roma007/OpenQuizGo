## 1. 目标与范围

- 交付目标：同一个守护端 APK 在**安卓平板**上用触摸完成登录、查看状态、全屏答题、被拦截；电视端行为不变；服务端与家长端能区分「电视 / 平板」。
- 不包含：iPad、设备所有者托管、防卸载、跨设备额度合并、APK 下载页。

## 3. 关键实现约定

1. `FormFactor` 结果只在启动时算一次，缓存为 `val current: FormFactor`（`enum class { Television, Touch }`）。
2. 平板界面统一放 `tv/app/src/main/java/com/openquizgo/guard/ui/pad/`，**禁止**在其中写业务判断，只消费 `GuardViewModel` / `QuizRepository`。
3. 电视界面 `ui/*.kt` 只允许改「按 FormFactor 分流」那一行，其余不动。
4. 平板发送登录请求时带 `platform="pad"`；电视不传（服务端默认 `tv`），避免老版本协商问题。
5. 平板界面宽度适配：内容最大宽度 720dp 居中，触摸目标 ≥ 48dp，字号不用电视的放大值。

## 4. 验证方式

| 层 | 方式 |

| Flutter | `flutter test`；`TvDevice.platform` 解析与「平板」标识渲染 |

| 手工（电视） | 创维上复跑 081/082/083 的验证清单，确认无回归 |

## 6. 回滚方案

- 客户端：APK 回退到上一版本即可，服务端 `platform` 字段可选、无迁移，不回滚也兼容。
- 服务端：`platform` 解析失败即按 `tv` 处理，回滚不影响已有电视设备。
- 不涉及数据库迁移，**无回库风险**。
