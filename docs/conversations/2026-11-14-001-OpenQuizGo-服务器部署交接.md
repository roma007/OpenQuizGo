## 3. 已经做过的关键改动（不要回退、不要"优化"掉）

### 3.1 nginx 用 host 网络

  web 服务是 network_mode: host，不再做端口映射。
  原因：经 docker-proxy 转发时源 IP 会被改写成 172.19.0.1，allow/deny 会把自己人也拦掉（403）。
  host 网络下 nginx 能看到真实客户端 IP。

### 3.2 nginx 访问控制

  atlas.conf / quiz.conf 都是：
      listen 8081;   /   listen 8082;
      allow 127.0.0.1;
      allow 100.64.0.0/10;
      deny  all;
  公网访问 8081/8082 会被安全组挡掉，nginx 再挡一层。

### 3.3 Tailscale 与阿里云 100.64.0.0/10 的冲突修复（重要）

  tailscaled 默认规则：
      -A ts-input -s 100.64.0.0/10 ! -i tailscale0 -j DROP
  而阿里云内网服务（元数据 100.100.100.200、内网 DNS 100.100.2.136/138、
  云安全中心 100.100.30.26 等、云备份 HBR 100.100.0.28、
  OSS 内网 oss-cn-<region>-internal → 100.115.33.x）都在这个段内，
  返回包会被内核丢弃，表现为「能 ping 外网但上不了网」。

  已修复（不要删）：
      -A ts-input -s 100.64.0.0/10 -i eth0 -j ACCEPT
  持久化：
      /usr/local/bin/tailscale-aliyun-fix.sh
      /etc/systemd/system/tailscale-aliyun-fix.service
      /etc/systemd/system/tailscale-aliyun-fix.timer   （开机 30s + 每 5 分钟自愈）
  仓库文件：scripts/tailscale-aliyun-fix.sh、deploy/systemd/tailscale-aliyun-fix.*
      （注意：目前是 untracked，尚未提交）

  如果哪天看到「云安全中心客户端异常离线」「文件备份失败，备份点未生成」这类短信，
  先查这条规则在不在，不要去控制台重装客户端——重装解决不了网络层问题。
